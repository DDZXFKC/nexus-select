## 2. 「購入可能な状態」の定義

来訪者が以下の流れを最後までたどれる状態を「購入可能な状態」とする。

1. 商品ページで商品・カラー・サイズを選ぶ
2. 「在庫を確認する」ボタンから在庫確認を依頼する
3. 運営側が在庫を確認し、確保見込みが立てば購入案内を送る
4. 購入者が決済して購入を完了する
5. 購入者が注文追跡で注文の状況（買い付け・検品・発送の進捗）を確認できる

## 3. 作業項目

進め方は全項目共通で「Localで実装 → 魔王ちゃんが実機確認 → GLM検収」の順（第5節）。

### A. 在庫確認フローの実装
- 内容：商品ページの購入ボタンを「在庫を確認する」に置き換え、問い合わせ受付 → 在庫確認 → 回答 → 購入案内、までの一連のフローをLocalで実装・検証する。
- 要件：
- 全商品・全カラー・サイズに対応すること。
- 在庫確認の依頼時点では注文・決済を発生させないこと。
- 在庫確認の結果（確保可／不可）を購入者へ回答し、確保可能な場合のみ購入案内へ進めること。
- 商品ページの表示は「海外お取り寄せ」の表現に統一すること。
- 状態：仕様は確定済み。Localでの実装・検証は未着手。

### B. 注文追跡の公開前4点
- 方式：自作プラグイン NEXUS ORDER TRACKER（A案、確定済み）。
- 公開前に解決する4点（いずれも実検証・実テストが未実施）：
1. 追跡番号発行時の購入者通知が届くこと。
2. パートナー専用画面（パートナーは担当注文のみ閲覧・登録可）。
3. 他の購入者の注文・検品写真が見えないことの実検証（検品写真は購入者のみ閲覧可）。
4. メール失敗時に通知が失われず、重複送信もしないことの実テスト。
- 補足：追跡番号の訂正履歴を記録する仕様は確定済み。
