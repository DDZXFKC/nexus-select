# 在庫確認フロー（購入可能化計画 項目A）設計案 v1（Claude、2026-11-20 11:40）

根拠：購入可能化計画 3985946（オーナー決定「カテゴリ追加より購入可能な状態」、サイト実装＝Claude）、確定仕様 docs/owner-mandatory-storefront-purchase-flow-2026-11-19.md。GLM 検収前提。決済（KOMOJU、未申込）と注文追跡（NEXUS ORDER TRACKER）は別項目。既存デザイン・カラー/サイズ/画像/価格UIは変えない。

## 段階分け（Local で順に実装 → 魔王ちゃん実機確認 → GLM 検収）
### 段階1：商品ページと在庫確認の受付（決済なし）— 今すぐ着手できる
1. 表示：価格付近に「海外お取り寄せ / 国内送料無料」。購入ボタンの直下に案内（ご注文後に海外ショップから買い付け／検品後にお届け／国内送料無料・配送状況の確認が可能）。お届け予定日数は、実証済みの配送ルートが決まるまで表示しない（仕様「未確定の固定日数を作らない」）。
2. ボタン：「ADD TO BAG」を「在庫を確認する」に置き換え（カラー・サイズ選択後に押せる。SOLD OUT サイズは押せない）。直下に「在庫確認は無料です。この時点では注文・決済は発生しません。」
3. 依頼フォーム（ボタンを押すと同じページ内に開く）：お名前・メールアドレス・（任意）メッセージ。商品・カラー・サイズ・表示価格は自動で添付。カートと決済には一切進まない。
4. 受付データ：WordPress 内に「在庫確認依頼」として保存（専用の投稿タイプ。注文データとは混ぜない）。状態＝受付／確認中／確保可／確保不可／期限切れ／取消。同じメール×同じサイズで未完了の依頼があれば新規を作らず既存を案内（重複防止）。スパム対策（nonce・送信間隔制限・ハニーポット）。
5. 通知：依頼者へ受付メール（「在庫確認は確保の保証ではない」旨を明記）、運営へ新着通知。管理画面に一覧（商品・サイズ・状態・受付日時）。
### 段階2：購入案内（運営が「確保可」にしたとき）
- 確認した価格・期限付きの購入リンクを依頼者へ送る。期限切れ・価格変動・確認後の売切れは、リンクを無効にして再確認を案内。リンクから進んだときだけカート・購入手続きに入れる（確認なしの購入は不可）。
### 段階3：決済
- KOMOJU 審査通過後に組み込み。仮売上・確定・取消・返金の実検証（計画 C）。

## GLM に決めてほしい点（段階1の着手前）
1. 段階1の範囲を上記で進めてよいか。
2. 依頼フォームの入力項目（お名前・メール・任意メッセージ）でよいか。電話番号は取らない想定。
3. 管理画面での状態変更は運営（オーナー／魔王ちゃん）が手で行う想定でよいか（自動在庫確認は GPT/GLM 側の別作業と接続するまで手動）。

決まったら段階1を実装し、オフラインテスト付きで正本に入れる。
