## 結論

## 状態と範囲の明確化
- `在庫取得アダプター実装 … 済` は「ステージング実装・GitHub CIオフライン試験PASS」であり、「Shoe Palace実サイトで在庫取得可・XServer反映済み」を意味しない。
- `400円ルールと最安店選択 … 済` はステージング模擬試験のみ。2026-11-22にオーナー既定ルール（値上げが400円以上のみ価格案内、399円以下は表示価格維持）と、複数仕入先全件チェックのPHPテストを追加した。CI run [44930786899](https://github.com/DDZXFKC/nexus-select/actions/runs/44930786899) 合格。
- `照合済みデータと原価計算の組み込み … 進行中` は「実装の枠組み・証拠ゲート構築済み、実価格・全費目・検収済み通貨・サイト決済率の入力元未接続」と明記。
- `XServer移行 … 済` はサーバー環境構築/サイト移動の完了と、在庫確認新UI・販売準備・本番購入・公開準備を区別。旧メール入力式在庫確認画面が存在していた11/21の実機監査 `docs/xserver-stockcheck-live-readonly-audit-2026-11-21.md` と一致する。
- `カテゴリー91件、色スウォッチ … 済` は構造/実装が済んだ範囲と、**全商品・多色親の表示・色別説明・画像と選択状態の最終監査**を区別。既存54商品色別説明の移行完了証拠が必要。
- `店舗シート9店分 … 済` はシートの書込/読戻し一致であり、各店舗の商品出品・原価確定・在庫確認・購買可能化完了ではない。
- `Kith 25,000件`、`Foot Locker 238件`、`全商品画像` などの数量は、一覧作成時の引継ぎ値として保持し、原本・時刻・重複除去後の件数があるまで最新実測と扱わない。
- `古い価格データ削除候補` は**原本を削除しない**。隔離・失効フラグ・保管ポリシーと確認を分離する。

## タスク台帳の扱い
- この文書により残存タスクを消し込んだり、自動でiPhoneリマインダーを変更したことにはならない。
- `補助金の遠藤さんへのメール` と `2025年確定申告e-Tax` は**事業周辺タスク**。関連依存（決済審査に使う申告書）はリンクするが、自サイトの公開チェックリストから独立して管理する。
- 残存タスクの「完了」は、コード登録・CIの合格だけでなく、必要なステージング/実機/本番証拠とオーナー承認を満たした場合にのみ付ける。
- **優先順**：現行エラー解消・SP在庫/価格・安全な商品照合と原価 → 他店舗データ接続 → 指定の最終購入UI/追跡 → 決済/法令/運用検証 → 公開前11条件判定。独立した合法定・配送・採用準備は並行。
- 価格基準は既存の `docs/stockcheck-owner-price-settings-verified-2026-11-21.md` が優先。400円差の意図を勝手に変更しない。原価費目は未確定値を0としない。
