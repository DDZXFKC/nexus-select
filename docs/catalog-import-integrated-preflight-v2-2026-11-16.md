# 商品大量投入・統合事前ゲート v2（オーナー決定反映・保存方式提案）
基準 c15b140c9b4d9bad611aa25831f1f9b2e697c7cd。docs/catalog-import-owner-decisions-2026-11-16.md がv1より優先。既存197商品、91カテゴリー、SKU、注文参照、デザインを維持。本書は仕様差分と保存方式提案で、実装・投入・公開承認ではない。
## 1. v1からの変更（確定）
- 自サイト売価=BUYMA売価−BUYMA販売手数料額。それ以外の価格差をつけない。自サイト決済手数料は別途利益計算に含むが、自サイト売価へ上乗せしない。実際のBUYMA適用料率・課税/丸め・計算基準を確認し、既存価格式を勝手に変更しない。
- ショップごとの収集Pythonを用意し、単一CLI/オーケストレーターから順番に実行する。既存店別アダプターを再利用。収集失敗は記録し独立店を続行。
- 店別原本・中間情報は独立保存し、共通正規化マスターで商品を事前統合する方式を採用しない。比較に必要な識別項目の共通インターフェースのみ用意する。重複判定は出力段階。確実な同一商品/色/サイズ/仕様のみ重複扱い、曖昧は要確認。先に取得した店を自動優先せず、全対象店の有効候補を比較する。
- 最終出力は1商品1行（色/サイズは別詳細、Woo出力は必要な親子行）。採用店と代替店の情報を保持し、別店側の最終出力から同一商品を抑制。サイズごとに仕入先が違う場合はサイズ単位の選択情報を保持。既存SKU/商品IDを店切替で変更しない。代替店の表示は運営用、顧客への公開とは別。
- 原価計算は適用条件を満たすクーポン価格を基本とする。v1の通常原価で最低利益達成を全商品に強制する規則は廃止（オーナー決定と矛盾）。通常価格は比較・失効時の再計算・代替判定に保存する。
## 2. 保存方式の比較・推奨（未承認）
現物確認: research/online/local-pkg/stage3_catalog.py は sqlite3、runs/queue/captures/observations/latest、raw BLOB、run/variantキーを使用。stage2_review.pyもSQLite observationsを使用。既存スキーマを無断変更せず、DBファイル実物・レコード・バックアップ・競合・容量を確認して再利用範囲を確定。
推奨: iMacのローカルSQLite＋不変原本ファイル＋Sheets/CSVの派生閲覧出力。店ごとのDBまたは既存DB内のstore_idで厳密に分離（物理方式は既存DB確認後選定）。出力決定DBは別に置き、店別観測を変更しない。SQLiteは追加サーバ費用なし、トランザクション・索引・一意制約・途中再開・SQL比較・差分更新が可能。単一writerで短いトランザクション、ローカルディスクに保管、実行中のDBをDrive同期フォルダで共有しない。オンラインバックアップAPI等で整合したバックアップを作成し復元検証。画像はファイル保存＋パス/ハッシュ、既存raw BLOBは容量実測後判断。
CSV/JSONのみ: 単純・可搬だが複数ファイル整合、同時更新、重複/履歴の管理が難しい。原本/入出力には採用。
Google Sheetsのみ: 人間の確認に優れるが、大量サイズ行、履歴、競合、更新API、関係整合性の正本管理には不向き。要確認/採用候補/例外一覧の派生ビューとする。手動承認はID付き入力を取り込み監査履歴化。
Supabase/PostgreSQL: 複数PC・担当者の同時利用、権限、遠隔アクセスに有利。ネットワーク/管理/費用/移行が追加。必要性が生じた時点で専用スキーマまたは別環境へ移行検討。既存注文追跡用本番DBには変更しない。
## 3. 段階保存と処理
L0 店別原本: store_id/run_id/取得日時/URL/HTTP結果/原文hash。原本不変。実際の413点items.csvは別正本、上書き禁止。
L1 店別抽出: shop_product_id/variant_id/商品名/品番/色/サイズ体系/在庫/価格/画像/分類/証拠。未知はnull。
L2 店別条件: coupon_rules/coupon_checks、送料、税、為替、代行費、返品、配送、取得鮮度、原価シナリオ。店別情報を保つ。価格・在庫の観測履歴を保存。
L3 比較判定: 店別の読み取りビューから同一性を検証して候補選択。最終採用理由、候補ID、サイズ別適格性、利益、検証日時、除外理由を decision_run に保存。優先順は適格性→原価/利益→配送/返品/確実性（同点ルール・利益下限は承認事項）。採用店固定でなく再評価可能。原本を束ねる共通商品マスターは作らない。最終出力用の安定IDと既存Woo ID対応のみ保持。
L4 出力: 出力確定ID単位で1商品、主仕入先、代替仕入先一覧（DBでは関連行、CSV/Sheetsはセル内JSONまたは可読一覧）、サイズ別仕入先、両価格、承認状態。Woo/BUYMA用は派生。未確定/HOLDは販売出力と分離。マニフェストhash・版・出力履歴を保存。
## 4. クーポン運用（確定方針＋安全制御案）
coupon_rulesにcode/割引方式/対象variant/除外/最低購入額/国/アカウント/初回/利用回数/併用/期限/timezone/証拠、coupon_checksに実適用結果・日時・数量・税送料を記録。対象サイズと現在の条件を確認し、適用可能なら割引後価格で原価算定。未確認は割引を勝手に適用しない。適用不能なら通常価格または代替店を使い再判定。通常価格は安全比較用で、価格決定の一律下限にはしない。
期限前停止/再計算、定期同期、注文前の価格在庫クーポン再確認、失効/回数制限/数量変更で採用店再判定。購入できない場合は新規販売停止。成立済み注文の価格変更・追加請求なし。外部クーポンが注文後買付まで有効とは保証できないため、失効時の赤字許容額・代替店条件・履行/返金の運用は未決事項として公開前に確定。クーポン依存という理由だけで一律HOLDにするv1ルールは削除するが、未確認価格・未確定リスク条件は販売承認しない。自動購入なし。
