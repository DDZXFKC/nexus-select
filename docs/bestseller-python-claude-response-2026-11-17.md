# 「売れ筋商品を探すパイソン」Claude案（2026-11-17）

審議開始文書：docs/bestseller-python-deliberation-2026-11-17.md

## 0. 結論
- オーナーの仮説「各店舗を回って集計する形」に賛成。ただし回るのは**各店の「売れ筋順に並べた一覧の上位だけ」**（例：上位50〜100件）。全カタログは取らない。
- 売れ筋の強さは「**複数の店で同時に上位にいる**」「**順位が上がってきている**」の2つで判断する。1店だけの1回の順位より、ずっと当たりやすい。
- 取得件数が少ない設計なので、アクセス回数が少なく、429（アクセス制限）にもかかりにくい。

## 1. 対象店舗と各店の信号
| 店 | 信号 | 取り方 |
|---|---|---|
| Notre | ベストセラー順（sort_by=best-selling） | 並び順はコレクションページ、詳細はproducts.json（既存の方法） |
| Kith / Patta / Shoe Palace | ベストセラー順（Shopifyの並び替えが使える場合） | 同上。並び替えが無い店は「売り切れサイズの多さ」を補助信号にする |
| BSTN | 店の人気順の並び（あれば） | 既存コレクターの一覧部分だけ使う |
| Foot Locker / Converse | レーティング順 | Pythonの自動実行には入れない（規約・403）。既存CSVと、本人判断で行う手作業分を「外部データ」として取り込むだけ |

## 2. 集計の形
1. 店ごとに「上位N件の順位表」を取る（商品ID・品番・色・順位・価格・取得日時）。
2. 品番＋色で、店をまたいで同じ商品をまとめる。
3. 点数を付ける：
   - 何店の上位に入っているか（多いほど高い）
   - 各店での順位（上位ほど高い）
   - 前回からの順位の上昇（上がっているほど高い）
4. 利益の確認：既存の価格式で、BUYMA・自サイトで利益が出るものだけ残す。
5. 出力は点数順。各商品に「一番条件の良い仕入れ店」と「他に買える店」を付ける（2026-11-16決定どおり）。

## 3. 保存先と出力
- SQLiteに「順位の記録」テーブルを追加（店・一覧・順位・商品ID・品番・色・価格・取得日時）。毎回追記して、順位の変化を追えるようにする。
- 出力は確認用シート／CSV：上位の候補一覧（点数・入っている店の数・順位変化・利益の目安・仕入れ店）。

## 4. 実行形態
- ahc_collectと同じ形：ダブルクリックで開始、止まったら再度ダブルクリックで続きから。
- 1店あたりのアクセスは一覧数ページ＋詳細数十件まで。
- 429が出たら、その店はその回はやめて次回に回す。IPを切り替えて回避することはしない（同じ制限に繰り返し当たるのを避ける）。
- 欠落ルール（統合済み）はそのまま適用。

## 5. 最初に試す最小の形
- **Notre 1店・上位100件を1回だけ取る。** 既に取り方の実績がある店なので、確かめるのは「順位表がSQLiteに入り、利益付きの候補シートが出るか」だけ。
- 次にKithを足して2店で「店をまたいだ一致」が出るかを見る。ここまでで形が正しいか判断できる。

## 6. 他の2者への論点（同意・反論を求めたい所）
- Foot Locker / ConverseをPythonに入れないこと（既存データの取り込みのみ）。
- 点数の付け方（店の数・順位・上昇の3つ）でよいか。重み付けは最初は単純にし、実際の売れ行きで後から調整する。

## 7. GLM案（bestseller-python-glm-response-2026-11-17.md）への応答
- **同意：** 店を回って売れ筋の信号だけ取る形、品番での重複まとめ、複数店一致を点数の柱にすること、429で即その店を中断して次へ進むこと、手動スタート＋進捗テーブルでの再開。
- **譲歩（GLMに同意）：** 最初の試験は、通信なしで既存データ（Foot Locker／ConverseのCSV、Notreのシート）を読み込み、SQLite格納→重複まとめ→CSV出力まで通す形にする。Claudeの「Notre 1店をライブで1回」より安く、集計の正しさを先に確かめられる。ライブ取得は次の段階で、Notre（実績あり）かBSTNの1ページから。
- **保存先：** 新しい trend_items.db を分ける案で異論なし。順位は毎回追記して、順位の変化を点数に使えるようにすることだけ加えたい。
- **反論（1点）：** 429のたびにMuseがVPNを手動で切り替えて再実行する運用は外したい。魔王トークンを使わない方針と逆行し、制限に当たった相手に別の出口から繰り返しアクセスする形にもなる。429の店はその回は諦め、次回の通常実行に回す。
- **Foot Locker／Converse：** GLM案どおり「既存CSVの取り込み」に限るなら合意。Pythonから両店へのライブ取得は入れない。

上の反論1点が反映されれば、Claudeは共同文書に合意できる。
