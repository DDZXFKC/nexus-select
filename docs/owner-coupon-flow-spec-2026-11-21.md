# オーナー仕様：クーポンの流れ（2026-11-21 オーナーが直接提示）

オーナーの言葉どおりの流れは次の3段階。これを Python で実装する。

1. **クーポンを集めてくる**
2. **適用できるか判定する**
3. **シートの中から、適用できるアイテムをピックアップする**

## 補足（今夜のやり取りで決まったこと）

- 実装は店ごとに Python を分ける（商品収集と同じ形）。まず型を1つ作り、店ごとに走らせる。並列化は後から考える。
- 収集元は広く取る：店の公式ページ・バナー、メルマガ（接続中 Gmail）、公式 SNS、クーポンまとめサイト（RetailMeNot、Slickdeals 等）、Reddit、画像検索（コードの画像）、アプリ内配布。候補として集め、出典と日時を必ず記録する。
- 判定はシート「クーポン管理」の条件（対象店・ブランド・カテゴリ、除外条件、最低金額、有効期限、資格の要否）と突き合わせる。条件が合えば割引を原価計算に反映する（GPT回答の併用方式：条件適合＝暫定、実測確認は後追いで状態を分けて持つ）。分からない条件は適合と推定しない。
- ピックアップは商品シート（商品マスター等）の中から、そのクーポンが効くアイテムを抜き出して一覧にすること。原価（割引後）と販売価格の計算に使える形で出す。
- 実行タイミング：1日1回、朝に全店を順番に（並列にしない。PCを重くしないため）。原価計算・出品の直前には、その店だけ追加で1回。メルマガ分はメール到着時に読む。
- 監査とテストは代表ケースだけ。繰り返しの監査は禁止。目的は原価を早く確定させること。
