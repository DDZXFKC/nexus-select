# 在庫確認 最終設計 v3：その場で判定 → カートへ（Claude、2026-11-21）

**この文書が在庫確認の設計の正本。**
- 根拠はオーナー決定（2026-11-21 12:32 頃、魔王ちゃん経由）。メール返信方式（決定3）と、Claude 最終設計 docs/stock-check-auto-flow-design-final-claude-2026-11-21.md は superseded。
- GPT 実装設計 docs/stockcheck-inline-cart-flow-redesign-gpt-2026-11-21.md（e12e4f7）を土台にする。内容の大部分に同意する。
  - 同意しない点・抜けている点は §6 に書き、その答えをこの文書に取り込んである。
- 担当：サイト（商品ページ・ポップアップ・SOLD OUT 表示・カート連携・実画面確認）＝Claude。判定エンジン・価格・サーバー側の検証＝GPT。
- サイトの正本は XServer。**どの変更も、サーバーの現行ファイルとの差分を確かめてから反映する。実物で確かめるまで「できた」と言わない。**

## 1. オーナー決定（確定）
1. 結果はメールで返さない。ポップアップでその場で判定する。判定中はスピナーを出す。
2. 「在庫あり」とは、カートに入れられること。
   - 在庫があれば、ポップアップに「在庫確認できました。カートへ移動できます」と出し、カートへ進めるようにする。
   - 在庫が無ければ、そのサイズを SOLD OUT 表示にする。
3. 在庫確認をしないと買えない（既定）。
4. 買い付け先ページから現在価格を読む（決定1）。価格差400円ルールは残す（決定2）。返信メールが無くなったので、案内先はポップアップになる。
5. 価格が変わりうる5つの事案は、サイトの常設ページとポップアップで説明する（addendum §1）。

## 2. お客様の操作と画面（サイト側、Claude）
1. 商品ページでカラーとサイズを選ぶ。
   - 未選択や、すでに SOLD OUT のサイズでは「在庫を確認する」を押せない（既存どおり）。
2. 「在庫を確認する」を押すとポップアップが開く。中身は次のとおり。
   - 選んだ商品・カラー・サイズ
   - 価格が変わりうる5つの事案の説明
   - 「在庫を確認する」の実行ボタン
3. 実行するとスピナーと「在庫を確認しています…」を出す。ボタンは押せなくする（二重送信を防ぐ）。
4. 結果に応じた表示
   - **あり（掲載価格）**
     - 表示：「在庫確認できました。カートへ移動できます」
     - ボタン：［カートへ進む］
     - 押すとその場で、そのサイズを1点カートに入れ、カート画面へ移る。
   - **あり（価格案内。差が400円以上）**
     - 表示：「在庫確認できました。現在の販売価格は ◯◯円です（掲載価格 △△円）。」
     - ボタン：［この価格でカートへ進む］［やめる］
     - 押したときだけ、◯◯円でカートに入れる。
   - **なし**
     - 表示：「このサイズは現在在庫がありません」
     - ポップアップを閉じると、そのサイズのボタンが SOLD OUT（押せない）になる（§4）。
   - **確認できず**（つながらない・読めない・価格が分からない・時間切れ）
     - 表示：「現在、買い付け先の在庫を確認できませんでした。時間をおいてもう一度お試しください。」
     - SOLD OUT にはしない。
5. ポップアップを閉じたら、判定の途中でも画面は元に戻る（裏の処理は捨てる）。カラーやサイズを変えたら、前の結果は使わない。

## 3. 判定の流れ（GPT 実装。長い通信を避ける形にする）
- 1回の問い合わせで30〜60秒待つ作りにはしない。XServer の PHP 実行時間の上限や、途中経路のタイムアウトに当たる恐れがあるため。
- 代わりに、**画面が短い問い合わせを繰り返す**形にする。
  1. `start`：ブラウザが選択を送る。
     - サーバーが商品・カラー・サイズ・バリエーションの一致を確かめる。
     - 照会の予定（買い付け先候補の順番）をサーバー側に作り、照会IDだけを返す。
  2. `step`：ブラウザが照会IDで繰り返し呼ぶ。
     - サーバーは毎回1店だけ照会する（取得1回＋2秒後の即時再試行1回まで、タイムアウト8秒）。
     - 返すのは「続く」か「最終結果」。
  3. 全体の上限は**45秒**（GPT 案の30〜60秒の中間。設定値 `inline_budget_seconds`）。超えたら「確認できず」。
- 買い付け先のURL・原価・店の情報は、ブラウザに一切出さない。判定と価格の計算は、すべてサーバー側で行う。
- 判定部品（StockChecker・OfferResolver・価格の計算し直し）は、オーナー決定どおり GPT の設計を使う。
  - 「最安の店を選ぶ」「掲載価格以下が見つかったら打ち切る」「全店品切れの確定だけをなしとする」「不明が残れば確認できず」は前の最終設計 §3 と同じ。
- **言語の確認（GPT・サーバー担当）**：WordPress のリクエストの中から Python を呼べるか（XServer で exec などが使えるか）。
  - 使えなければ、判定部品を PHP で書く。Python 版はその仕様とテストの元として使う。
  - どちらにするかは XServer で実際に試して決める。
- 403/429 の店は、一定時間すべての問い合わせから照会しない。回避はしない。同じ IP からの照会は20秒に1回まで（設定値）。

## 4. 「なし」の SOLD OUT 表示（決め方）
- 照会した全店で、そのサイズの品切れが確定したときだけ、SOLD OUT にする。
- **他のお客様にも同じく SOLD OUT と見せる。** ただし WooCommerce の在庫データ自体は書き換えない。
  - 書き換えると、シート→サイトの商品データの流れ（魔王ちゃん／GPT の取り込み）とぶつかるため。
  - 代わりに、そのバリエーションに「在庫確認で品切れ確定」の印と時刻を付ける。
- 印の有効期間は**24時間**（設定値 `oos_mark_hours`）。期間中は、テーマの SOLD OUT 表示（既存の main.js と ahc-soldout.php）と、サーバー側の照会・カート投入の拒否の両方がこの印を見る。
- 24時間たてば、再び確認できる。
- 印が付いたことは記録に残す。10日連続の SOLD OUT で出品を止める判定（別系統）へ流すかは、その仕組みの担当が決める。

## 5. カートとの関係（サーバー側の門）
- **購入許可**：「あり」が確定したら、サーバーが購入許可を出す。内容は次のとおり。
  - 許可キー：ランダム・使い切り・セッションに紐付け
  - 商品・バリエーション・カラー・サイズ
  - 選んだ買い付け先
  - 販売価格（掲載価格か案内価格）
  - 期限：**5分**（GPT 案に同意。カートに入れるまでの期限）
- **カート投入**
  - 通常の追加と、ブロックカート（Store API）の両方の入口で、許可を確かめる。許可が無ければカートに入れない。
  - カートの全面許可（`ahc_stock_check_allow_cart=true`）は使わない（GPT 案に同意）。
- **カートに入った後**
  - カートの行に、許可の内容（販売価格・買い付け先・確認時刻）を保存する。
  - 価格はこの保存値を使い、合計を計算し直しても変わらないようにする。
- **カートに入れてからの有効時間**（GPT 案で抜けていた点）
  - 5分の期限はカートに入れるまでのもの。入れた後に決済画面で5分を過ぎるたびに取り消すと、買えなくなる。
  - 提案：カートの行は**60分**有効（設定値 `cart_hold_minutes`）。注文確定の時点で60分を過ぎていれば、その行だけ在庫確認をやり直してもらう。
  - 決済は未導入なので、実際の値は決済を入れるときに確かめる。
- 表示中の販売価格（掲載価格）は書き換えない。
- 案内価格は、そのお客様のカートの行にだけ適用する。

## 6. GPT 実装設計（e12e4f7）への監査

## 7. オーナーに確認する点
1. **ポップアップの名前・メール入力は、まだ要るか。**
   - 12:23 の決定では必須だったが、結果をメールで返さなくなったので、使い道が無くなる。
   - 不要なら、入力欄なし（説明と実行ボタンだけ）にして、個人情報を受け取らない。90日保存の対象も無くなる。
   - 要るなら、何に使うか（例：再入荷の連絡は以前の決定で範囲外）を決めてほしい。
2. 設定値の初期値（変えたいときだけ）
   - 全体の上限：45秒
   - 品切れの印：24時間
   - カートの行の有効時間：60分
   - 同じ IP からの照会：20秒に1回

## 8. 旧方式から消えるもの
- 結果メール、受付メール
- 5分以内の送信監視
- 照会を後で処理する仕組み（cron の1分ワーカー、WP-CLI の pending/result）
- 受付IDの発行
- 依頼データの非公開保存と90日削除（§7-1 で入力不要なら、保存するものが無くなる）
- 運営への通知は、**読めない店があったとき**だけ残す（決定3の「取得方法の問題として別に対処」）

## 9. 実画面での確認（反映後、XServer で。Claude）
次のすべてを、PC と iPhone で実際に操作して確かめる。
- サイズ未選択では押せない
- スピナーが出る
- 「あり」→ そのサイズだけがカートに入り、カートへ移る
- 価格案内 → 同意したときだけ案内価格でカートに入る
- 「なし」→ SOLD OUT になる（別のブラウザでも SOLD OUT）
- 「確認できず」→ SOLD OUT にならない
- 許可なしでカートに入れようとすると拒否される（URL直打ち・ブロックカート）
- ポップアップを閉じる、カラーを変える、ページを再読み込みしたときの戻り方
