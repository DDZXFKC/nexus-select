# オーナー要件：取引店舗が増えたらクーポン対象も自動で増えること（2026-11-18）

オーナーの希望（原文の趣旨）：「取引店舗が増えると、自動的に増えたショップに対応するクーポンも自動で拾いに行く」

## 要件
1. L0の対象店舗レジストリは、コード内の固定リストにしない。取引ショップの正本（商品管理の記録）から読み込む形にする。
2. 正本に新しい取引ショップが追加されたら、コード変更なしに、そのショップのクーポンが自動でゲート通過・収集対象になる。
3. 逆に正本から外れたショップは対象から外れる。
4. 正本が空・取得不能の場合は全件拒否（全許可フォールバック禁止は維持）。

## 担当への反映
- Grok（入口ゲート）：レジストリは外部から受け取る現行仕様のまま、その供給元を「取引ショップの正本」にすること。ショップ名をコードに埋め込まない。
- GLM（収集・判定）：収集対象の店舗集合は同じレジストリから取得し、追加店舗へ自動で追随すること。
- GPT：本要件を設計・監査の前提に含めること。

※ 本要件は設計・実装の形を定めるもので、ライブ取得の解禁ではない。GPT監査が通るまでライブ取得・価格反映の禁止は継続する。
