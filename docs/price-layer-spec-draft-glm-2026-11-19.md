## 第1部 価格データ管理仕様

### 1. 目的
- ショップごとに価格・定価・在庫・取得日時をセットで管理する
- 正本と履歴を分離し、いつ・いくらで確認されたかを追跡可能にする
- 将来の販売価格反映に備えたデータ基盤を、反映処理を実装せずに整える

### 2. 管理項目(価格レコード)

| # | フィールド | 型 | 説明 |
|---|---|---|---|
| 1 | ショップID | 文字列 | ショップ識別子 |
| 2 | 商品ID | 文字列 | ショップ内商品識別子 |
| 3 | 商品名 | 文字列 | 補助情報 |
| 4 | 価格 | 数値 | 実勢販売価格 |
| 5 | 定価 | 数値 | 掲載定価・参考価格 |
| 6 | 在庫 | 数値/状態 | 在庫数または在庫状態 |
| 7 | 取得日時 | 日時 | 正本判定の基準 |
| 8 | ステータス | 列挙 | 確認済み/未確認 |
| 9 | 取得元・手段 | 文字列 | 出典・取得方法 |
| 10 | 備考 | 文字列 | 自由記述 |

- 4〜7はセット管理。一部のみの更新は不可(差分があればレコード全体を新規取得)

### 3. シート構成案
- 管理単位はショップごと。同一商品でもショップ間で統合しない
- 命名規則(案)：
  - 正本:`price_{shopId}`
  - 履歴:`price_{shopId}_hist`
- 履歴シートは正と同じ項目+正本期間(開始日時・終了日時)

### 4. 正本の決め方
- 正本 = 同一(ショップID×商品ID)のうち、**「確認済み」かつ「取得日時が最大」**のレコード
- 未確認データはどれだけ新しくても正本にならない
- 取得日時が同一の場合は、システム登録日時の新しい方(案)
- 更新手順：
  1. 新データを「未確認」で登録
  2. 確認操作により「確認済み」へ昇格
  3. 旧正本より取得日時が新しければ、旧正本を履歴へ移動し新レコードが正本となる
- 価格・定価・在庫が現行正本と完全一致する再取得：正本更新せず取得事実のみ履歴へ記録(案・未決)

### 5. 履歴の残し方
- 履歴シートへの追記のみ。上書き・削除は原則禁止
- 各履歴レコードに正本期間(開始・終了日時)を記録し、期間価格を追跡可能にする
- 正本にならなかった未確認データも取得記録として保持

## 第2部 原価計算・クーポン適用仕様

### 1. 目的
- 原価は**適用確認済みクーポンの割引を反映した価格**で計算する(本人決定)
- クーポンの「発見」と「適用確認」を別データで管理し、未確認クーポンを原価に混入させない

### 2. 管理項目

**クーポン発見シート `coupon_{shopId}_found`**

| フィールド | 説明 |
|---|---|
| クーポンID | 発見単位の一意ID |
| クーポンコード/名称 | 識別情報 |
| 割引内容 | 率または定額、適用条件 |
| 発見日時/発見元 | いつ・どこで見つけたか |
| 適用確認ステータス | 未確認/適用確認済み |

**クーポン適用確認シート `coupon_{shopId}_applied`**

| フィールド | 説明 |
|---|---|
| 適用確認ID | 一意ID |
| クーポンID | 発見シートへの参照 |
| ショップID×商品ID | 適用対象(価格レコードへの参照) |
| 確認日時 | 適用を確認した日時 |
| 割引後価格 | 実際に確認できた値 |

### 3. 原価計算ルール
- 原価 = 正本価格(第1部§4)に**適用確認済みクーポンのみ**適用した値
- 発見のみのクーポンは原価に反映しない
- 原価計算は**適用確認シートのみ参照**する(発見シートは直接参照しない)
- 適用クーポンIDを計算根拠として残し、再計算・検算を可能にする

### 4. 発見/適用確認の分離(運用)
- 発見：いつでも登録可。原価には影響しない
- 適用確認：「このショップ・この商品に効く」を確認したときのみ登録
