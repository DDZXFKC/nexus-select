## 固有特性と現時点で確認済みの限界
### Claude：サイトの実行責任者
- ユーザーが「ClaudeはChromeで動ける」と明示。ChromeでXServerの閉じたサイトを画面操作できる経路を優先する。実機ブラウザの認証・到達・書込権限は都度実測する。11/19の旧レポートではiMac接続が不可だったため、現在の接続が有効とは推定しない。
- GitHub取得・修正・テスト・コミット実績あり。11/19レポートでは10分ごと予約メッセージとMuseからのチャット送信で起動確認、GitHub push単体では起動しない。複数Claudeチャットがあるため本命セッションID/宛先の区別が必須。現時点でも10分起動が有効かは未確認。
- Claudeはサイト（テーマ/UI/画像/カテゴリ/カート/在庫確認の画面側）を担当。Pythonの所有者ではない。Chromeが使えることをMuseのブラウザ制約緩和とみなさない。
### GPT：Python・技術実装の責任者
- GitHubでコード・自動化・検証・レビューを自力で進める。商品発掘、商品収集/クーポン、価格/在庫確認のPython部分。Claudeのサイトコードと重複編集しない。
- iMacのGUI、Claudeのチャット、Apple Remindersをこのセッションから直接操作・起動できると主張しない。GitHub更新のみではClaude・Museは即時起動しない。
### Muse：リマインダー同期・運搬・iMac補助
- 正本リマインダーをmacOS側で読書きできる既存の経路で、開始時・30分ごとに確認。読めないなら最後の成功同期時刻を明記し、完了にしない。
- GitHubの成果物/版/次操作をClaude本命チャットへ直接運搬し、受領がそのセッションに到達したことを確認。オーナーをコピペ役にしない。iMacの実機確認やファイル入替などを必要な範囲で行う。
- docs/muse-browser-rule-2026-11-12.md のChrome使用禁止を厳守。Safariなど許可済みの手段だけ。Chromeしか使えないサイトUI作業はClaudeへ振る。computer_busy等が出たら停止理由だけ記録し、無関係タスクを並行実施。
- 実行担当は11/21にClaude/GPTへ移譲済み。Museが無理にサイト修正やPython書換えまで抱えない。

## 唯一の正本・同期
- タスク一覧、重要度、期限、完了、本人の判断 = **iPhone Remindersのみ**。正本の変更権限は既存のMuse経路。GitHub docs/Issues/SQLite/coordinatorは作業証拠と引継ぎキュー。第二のタスク正本は作らない。
- MuseはRemindersの各タスクIDとリンクさせた情報（owner、assignee、revision、artifact SHA、次操作、blocker、evidence）をGitHubに秘密抜きで記録する。GitHubからRemindersの完了/取消を勝手に判断しない。
- 作業結果→コミット/実機証拠→レビュー→MuseがRemindersへ更新→読み戻しの順。REMINDER_DONEはRemindersの実際の完了確認がある時だけ。

## 止めないための実行プロトコル
1. Museがリマインダーを読む→新規・変更・期限・ブロッカー・完了条件を整理→Claude/GPTの担当へ直接渡す。
2. ClaudeとGPTは相互に独立なタスクを同時に進める。Claudeはサイト画像・レイアウト・Chrome画面、GPTはPython・在庫判定ロジック。共通仕様はI/O契約だけ先に決め、相手の実装完了を待たずモックで作業。
3. それぞれ成果をGitHubの固定コミットSHAと実行証拠で保存する。重複通知は task ID + revision + SHA で除去。相手の作業が未完なら別のREADYタスクへ進む。レビュー待ちを「作業全体の停止」にしない。
4. Museは30分確認で新しい成果物と正本変更を照合、Claude本命チャットへ送達。Claudeの定期起動が今も有効ならそれを活用するが、pushで起きたとは記録しない。GPT定期監督は既存の有効な1時間間隔Automationを活用し、同種監視を重複新設しない。
5. 外部応答待ち、本人ログイン、支払、送信、公開は WAIT 状態へ移して独立案件へ移る。秘密や個人情報はGitHub公開リポジトリへ流さない。
6. 毎回「今終えた証拠」と「次のREADY」を残す。休止/利用制限時は次に起動した担当が最新SHA・Reminders更新時刻から続きだけ処理する。常時稼働を偽装しない。
