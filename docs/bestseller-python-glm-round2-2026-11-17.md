### 2. 3者合意の共同文書案（全文）

**【売れ筋商品発掘パイソン 共同仕様書】**

**1. 対象店舗と、各店で使う「売れ筋」の信号**
- **Notre**: ベストセラー順（既存342点データを流用）
- **BSTN**: 店の人気順・注目商品の信号（既存収集DBから抽出、または許可された範囲で取得）
- **Kith / Patta / Shoe Palace等**: ベストセラー順（Shopifyの並び替え機能等を利用。実物確認後、利用可能なもののみ登録）
- **Foot Locker / Converse**: カスタマーレイティング順（※評価順であり売れ筋順ではない。既存CSVの取り込みのみでPythonによる自動収集は行わない）
- **補助信号**: 売り切れサイズの多さ、順位の上昇傾向（ただし単独で売れ筋と断定しない）

**2. 集計の形（回り方、重複の扱い、ランキングの付け方）**
- **回り方**: 各店の売れ筋一覧の上位N件（50〜100件程度）のみを対象とし、全カタログは取らない。
- **入口と出口の分離**: 海外の売れ筋信号の収集（入口）と、国内の販売状況・競合・利益の確認（出口）を分離して設計する。
- **重複の扱い**: メーカー品番・カラー・仕様の一致をキーとする。複数店で被る商品は、買付条件（価格・在庫等）で1店をメインとし、他店を代替店として情報を残す。
- **ランキングの付け方**: 任意の重み付けによる単一スコアは作らない。以下の情報を列として持たせ、根拠付きで分類・並べ替えを行う。
  - 何店の上位に入っているか（マルチストア合致）
  - 各店での順位とその変化（前回からの上昇等）
  - 国内需要/希少性の証拠
  - 買付可能性と原価/利益の見込み

**3. 保存先と出力形式**
- **保存先（正本）**: 新規SQLite（`trend_items.db`）。既存の収集DBとは分離。
- **履歴保持**: 店・一覧・順位・商品ID・品番・色・価格・取得日時を毎回追記し、順位の変化を追えるようにする。
- **出力形式**: 確認用CSV（`売れ筋候補_YYYYMMDD.csv`）。発掘根拠、順位、国内状況、買付店・代替店、価格等を列に持つ。

**4. 実行形態（手動スタート、再開、429やIP制限への対処）**
- **実行環境**: iMac上でダブルクリック（`.command`等）で手動スタート。止まっても再開で続きから処理。
- **429・IP制限への対処**: 429が発生したら、その店はその回でスキップし、次の店へ進む。VPNの手動切替等によるIP変更での回避は行わない。次回の実行時に再試行する。403や自動収集禁止の店舗は即座に停止する。

**5. 最初に試す最小の形（1店だけの試験など）**
- **Phase 1（オフライン検証）**: 通信を発生させず、既存のCSV（Foot Locker / Converse）とシート（Notre）をPythonで読み込み、新規SQLiteへ格納 → 品番等による重複排除 → 根拠付きCSV出力までを行う。集計ロジックと出力形式が正しいか検証する。
- **Phase 2（ライブ試験）**: Phase 1が合格したら、実績のあるNotreまたはBSTNの売れ筋ページ1ページ分（20件程度）をPythonで取得し、同じパイプラインに流す。
