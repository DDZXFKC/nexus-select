# 相談：魔王ちゃんのトークンに頼らない商品データ収集の方法

## 問題（オーナーの指摘）
現在の収集は、魔王ちゃん（このAIエージェント）のトークン消費に頼りすぎている。ブラウザ操作、画面の読み取り、実行の監視や継ぎ足しなど「自由度の高い手作業的な収集」が中心になっていて、コストが大きく、継続性もない。これではダメだ、というのがオーナーの判断。魔王のトークンに頼らない方法を、3者で考えてほしい。

## 事実前提
- 各ショップの実際の収集方法は docs/collection-methods-per-shop-2026-11-16.md の通り。内訳を見ると、スクリプトで完結しているのはShopify系の products.json 取得とBSTNコレクターくらいで、Foot Locker（Web ScraperのChrome操作）、Converse（実ブラウザでグリッド読み取り）、Notre（スクリプトだが実行管理は魔王）など、魔王の作業が前提の部分が多い。
- 保存の仕組みは3者合意済み：正本はiMac上のSQLite（L0原本→L1抽出→L2条件→L3判定→L4出力）。
- 欠落の扱いは統合ルール確定済み（推測で埋めない／3層分類／参照表方式）。
- 収集の3系統方針（オーナー決定）：(1) Python自動収集が可能な店は共通収集エンジン、(2) Pythonでは技術的に収集できない店は魔王ちゃんがブラウザ操作で収集（ただし自動収集禁止の規約はブラウザ操作でも守る）、(3) 自動収集自体が規約で禁止されている店は許可された手動調査・公式データ提供など。今回の相談の中心は、この (2) をどう無くすか、減らすか。
- 実行環境：自宅iMacは平日日中オーナー不在で、夜間・無人実行が可能（定期実行の仕組みが使える）。魔王ちゃんのVMも常時稼働している。
- Foot LockerのWeb Scraper用サイトマップJSONは既にある（footlocker-com-2026-11-15）。ただし実行にはChromeの操作が必要だった。

## 相談事項
1. 魔王のトークンをほぼ使わずに（理想はゼロ、現実的には「結果の確認と報告だけ」）商品データを収集し続ける方法を設計してほしい。
2. 店舗ごとに、現在の方法からどう移行するか。Shopify系はスクリプトの定期実行で完結するはず。Web Scraper依存の店、ブラウザ読み取りが必要だった店はどうするか。
3. 無人実行の形：スケジュール、失敗時の自動再開、ログの残し方、欠落検出（統合ルールとの接続）、結果の保存（SQLiteへの取り込み）。
4. 規約面：自動化してはいけない店は自動化しない前提で、その店をどう扱うか（頻度を下げた手動のまま、対象から外す、公式データ提供の利用など）も含めてほしい。
5. 移行の優先順位：どの店から自動化すると、魔王のトークン削減効果が大きいか。
