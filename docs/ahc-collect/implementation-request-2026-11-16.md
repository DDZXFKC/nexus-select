## 作るもの（最小実装）
1. `ahc_collect.py`（共通入口）
   - 店ごとに順番に実行する。対象はまず Shopify 系：Shoe Palace／Kith／Patta／Notre。
   - `shopify_json` 取得部品：店ごとの設定（ベースURL＋コレクションslug一覧）に従い `/collections/<slug>/products.json` を limit=250・ページ送りで全件取得する。
   - 生JSONをそのまま保存する（L0）。あわせて SQLite に保存する。正本は iMac 上の SQLite（保存設計は既存のGLM設計案に沿う。最小では products／variants テーブル＋ユニークキー＝店ID＋商品ID／バリアントID）。
   - 再開ロジック：ユニークキーで取得済みを判定し、未処理分だけ続きから実行する。二重起動はロックファイルで防止。
   - 進捗（店名・件数）をターミナルに表示する。エラーは店単位で隔離し、他店は継続する。
   - 完了時に `report_YYYYMMDD.txt` を出す（店別件数・エラー・欠落・要判断事項）。
   - 正常系で LLM 呼び出しはゼロ。ブラウザ自動化・プロキシは使わない。
2. `商品収集START.command`
   - iMac のデスクトップに置き、ダブルクリックでターミナルが開いて `ahc_collect.py` が走るだけのもの。引数入力なし。

## テストについて（オーナー指示・厳守）
- 検証は統合最終案の合格条件3つだけ。各1回だけ実施する。
  1. 既存保存データで手動START 1回：1店以上の実商品・variant が SQLite に保存・出力され、値と原本が照合できる。
  2. Shopify 系1店で手動START 1回：現行商品・サイズ・価格・在庫が取得され SQLite に保存される。LLM 呼出0。
  3. 途中停止→再ダブルクリックで続きから完了。重複取得なし、エラー店は隔離され正常店は継続。
- **通ったテストは繰り返さない。合格条件以外のテストを足さない。** テスト範囲を広げたくなったら、実行前に魔王ちゃん経由でオーナーに確認する。
