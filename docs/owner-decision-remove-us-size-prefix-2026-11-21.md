# オーナー決定：商品サイズの先頭「US」を取り除く（2026-11-21）

## 依頼の意味
オーナーの原文：「勝手にUSつけて勝手に紐付け難しくして。US消したらいいだけやろ」

**確定：** サイズラベルの先頭だけの「US 」を削除する。商品説明やメーカーSKU、仕入先Shopifyサイズ、ブランド表の国別判定情報、cmは削除しない。例：
- `US 8.5` → `8.5`
- `US 3Y (23cm)` → `3Y (23cm)`
- `8.5` → 変更なし
- `UK 8.5`、`EU 42` → 変更なし

## 作業分担
- GPT：`tools/stockcheck_sp_join_contract.py` の照合ロジックを旧/新両表記に対応させ、merchant_variant_id/variation_idで厳密に固定、テストする。
- Claude：ChromeからアクセスできるXServerのWoo表示ラベル側について、書き換え箇所を調査し、現在表示されている商品ページの表記・WordPressの商品属性「サイズ」/variation属性・保存データを**同時に整合させる**安全な変更手順を用意する。担当外のPHP/JSは触らない。
- GitHubの既存証拠CSV `data/xserver-export/supplier-url-evidence-sample-2026-11-21.csv` は**2026-11-21時点の旧表示の証拠**なので、証拠文言を改ざんしない。移行後にはWooの最新表記を新エクスポートとして保存し、旧→新差分を記録する。

## XServerへの適用条件
- 現在のWoo商品親の属性選択肢、variation値、可変商品全件の「サイズ」ラベルがどこに保存されているか事前に確認。**子variationだけ、または親商品の選択肢だけを書き換えると選択できないサイズが出る**ので厳禁。
- 旧値→新値を全件列挙し、同じ親商品の複数サイズが削除後に**同じ文字列に衝突**しないことを確認。
- 変更前の全データをバックアップ、少数の公開商品（SP21376/GS19812を含む）で表示と購入対象variation IDを確認、XServerで選択/カート禁止などの既存動作が壊れないことを確認してから対象を広げる。
- 店舗側のUS/UK/EUの体系情報は内部データとして保持。削除対象は先頭ラベルに限り、「US 8」と「UK 8」を同一扱いにしてはならない。US/UK/EUを併売している親商品は**ラベル削除で衝突しうるのでHOLD**。
- サイトの新在庫確認APIは未導入。USの削除を理由に未実装APIや新ポップアップを同時に勝手に導入しない。
- XServerの書換えは実施証跡が無い限り未完了と報告すること。

## 重要
これまで、オーナーの指示なしに「USを付ける」のを正しい表示規則と説明したのは不適切だった。USはサイズ体系の**内部情報**に必要な場合は保持しても、顧客の表示ラベルに自動追加しない。今後の新規インポートでも表示ラベルへの付与を禁止する。
