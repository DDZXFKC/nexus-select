# 【撤回・訂正】2026-11-21 「US」を消す指示の解釈について

**最優先のオーナー指示（後続発言）**：
「localで保存してた時は紐づいてたやろ？抜いてきたデータを勝手に変更したら不具合起きるに決まってるやろが！！！！ 結びつけるためのデータを改ざんすんな！！！！」

## 先行する本ファイルの指示を撤回
以前この文書に記載した、XServer上のWooCommerce「サイズ」属性値、親商品属性選択肢、各variation属性値を一括して「USなし」に**書き換える指示は全面撤回**する。Claude・Muse・GPT・GLMはその指示を実行してはならない。これまでの変更前の値がどの処理の結合キーとして利用されているか確認せずに変える行為は禁止。

## 正しい優先順位
1. **Localで実際に紐付いていた結合の仕組みと元データを先に調査**する。SKU、variation ID、サイズ・カラーの生の属性値、仕入先の元の option 値を変更しない。
2. **取得元のデータは不変**。収集CSV・JSON、店舗別正本、WooCommerce親/variation属性、メーカーSKU、ショップSKU、仕入先product/variant ID、既存証拠CSVは原本として保持。原本のキーをリネーム・上書き・接頭辞除去して再保存しない。
3. **表示専用のラベル**を別途必要とする場合に限って、データを変更せずユーザー表示上でのみ「US 」を隠すことを検討。ただし、Localでの表示実装・実データ依存を検証するまでUI側にも変更を加えない。
4. **照合には必ず原本の値と識別子を使用**。Shopifyの`option1`とWooのサイズ表記が違う場合は、読み取り専用の派生比較値・証拠付きの対応表を作る方式に限る。比較結果を書き戻して原本を改変しない。Localで直接の対応関係がすでに存在するなら新方式を作る前に再利用を検討。
5. データの移行・編集を禁止し、変更が必要な場合は元データと差分・影響を示して別途承認を得る。バックアップと元データ復元可能性を維持する。

## 今までに実行した作業の範囲
- 前のGPTによる変更はGitHubの指示文と、オフラインの照合用Pythonコードに対するもの。
- **XServerの商品属性・variationの実データ変更はGPT側では実行していない**。Claudeがその後変更したかは別途実行ログにより確認。
- 旧指示「親商品・variation値を整合させてUSを消す」は**無効**とする。

**この訂正文書が優先**。他の文書に「USを元データから除去」「データを整形して統一」と書いてあっても、オーナーの明示許可なしでは実行しない。
