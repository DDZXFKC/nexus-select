# §27 — persistent discovery design after §26
Accepted: §26 ad9111c8, 182 tests, 187 candidates, 5 products, 40 variants, 45 Woo rows, 5 BUYMA rows, all HOLD, published/imported zero. Partial trial only. Strict full sweep not accepted.
Next implementation must separate discovery coverage from detail queue completion. Persist immutable per-page capture evidence (seed, requested page, capture UTC, raw SHA256, raw bytes, total, page count, ordered URLs, release exclusions); candidate identity exact scoped URL; first/last seen and observations, not a destructive replacement. Use one shared Fetch budget per invocation, persistent cumulative request ledger for a campaign, no retries on HTTP/robots failures. Explicit bounded page ranges, no automatic reset to evade limits. Recheck permissions before each invocation. Page drift and overlap recorded; no claim of snapshot completeness from mixed-time pages. Missing candidates never imply delisting or stock. Separate product detail queue with HOLD only, preserve historical observations, no production writes.
Acceptance: offline replay idempotency, changed totals/overlap, release exclusion, invalid shape/scope, interrupted capture and restart, budget exhaustion, stale permission, missing candidate not removed, queue completion not catalog completeness. Then bounded live test only after cross-review. Existing trial and strict discovery unchanged.
Open issue: §26 evidence records listing hashes but not raw listing bytes in the probe output; do not claim independent raw replay from that output. Need raw capture persistence in next implementation. No full sweep authorized by this design note.
