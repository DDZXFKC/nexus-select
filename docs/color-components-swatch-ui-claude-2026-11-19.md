# 色分解の丸窓：表示部をデータ駆動にした（Claude、2026-11-19）

根拠：GPT確定設計 70ee059（オーナー承認）の「Claudeは既存swatch表示部だけをデータ駆動にする」。
Museの実行順「まず1商品を2表→丸窓まで通す」の丸窓部分を先に用意したもの。Localへの反映は、Museがその1商品を通す時でよい。

## 変更
- theme/main.js：商品に色分解データがある場合、丸を左→右の等幅の縦帯で塗る（1色100%、2色50/50、3色1/3ずつ、4色以上は先頭3色）。先頭3色（3色未満ならその全部）の色コードのどれかが未確定なら、色を推測せず「未確認」の中立表示（白地＋点線の丸）。丸には色名を入れず、読み上げ用ラベル・ツールチップと見出し横の選択色名は色名全文（既存のまま）。
- theme/style.css：未確認表示の1ルールを追加。
- mu-plugins/nexus-variation-gallery.php：商品メタ _ahc_color_components を読んで window.NEXUS_COLOR_COMPONENTS として出力（不正な色コードは未確定扱い）。
- 色分解データがある商品はこの方式だけを使い、写真の切り抜きは混ぜない。データがまだ無い商品は今の表示（写真切り抜き→色名の丸）のまま。サイズ順・画像・価格・在庫・色名表示は変更なし。

## データの受け渡し（案：GPT・Museの確認が必要）
- シート（商品カラー表）→Woo の書き込みで、商品ごとに次を保存してもらう前提にした：
  - 商品メタ `_ahc_color_components`
  - 中身：{ "<pa_colorのslug>": [ {"name": "Black", "hex": "#111111"}, {"name": "Tough Red", "hex": null}, ... ] }（components_json の順番どおり。未確定は hex: null）
- この形でよいか、別の置き場所（タームメタ等）にするかは GPT の判断に従って合わせる。

## 確認済み（Claude側）
- main.js 構文チェック合格、PHP 構文チェック合格。
- 縦帯の作り方：1色→単色、2色→50%ずつ、3色→1/3ずつ の出力を Node で確認。

## 補足（Museの見本 0619648 を読んで）
- 丸窓は受け取った色コードをそのまま塗る。承認前の下書き（hex_status=DRAFT）を店頭に出さないよう、シート→Wooの書き込み側で「APPROVED_APPROX の色コードだけを hex に入れ、それ以外は null」にする前提とした（null の色を含む商品は未確認表示になる）。下書きの色でも見せたい場合は、この書き込み側の条件を変えれば足り、テーマ側の変更は要らない。
