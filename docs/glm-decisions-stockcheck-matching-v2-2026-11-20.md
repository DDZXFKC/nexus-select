## 1. 決定1：自動在庫確認への組み替え 設計要点

設計原則：問い合わせ1件ごとのオンデマンド確認のみ。常時クロール・定期巡回はしない。

### 1-1. 自動確認の対象範囲

- 対象：照合で特定された買い付け先の商品ページURL（＋ページが構造化していればサイズ/色バリエーション）
- タイミング：問い合わせ受信 → 照合成立直後に1回（＋リトライ）
- キャッシュ：同一URLはTTL 30分
- 判定方法：買い付け先別の設定ファイル（セレクタ＋在庫キーワード）＋取れない場合の汎用キーワードフォールバック
- 負荷：1問い合わせ原則1リクエスト。仕入先にBANされたら売上が死ぬので最低限の丁寧さを維持

### 1-2. 確認できない場合の扱い（3値）

- IN_STOCK（在庫あり確定）→ 自動返信（あり）
- OUT_OF_STOCK（品切れ確定。404・販売終了含む）→ 自動返信（なし）＋カタログ整理フラグ
- UNKNOWN（判定不能）→ リトライ2回（5秒後・30秒後）→ 解決しなければ「確認中」の自動返信を即送信（受付済＋24時間以内返信を約束）し、1時間後・6時間後に再試行 → 24時間で解決しない場合のみオーナーへ例外通知（日次ダイジェスト可）

オーナー通知はこの例外パスのみ。ただしオーナーがこれも不要と言う場合は、この1行を削るだけで他の設計はすべて成立する。
別扱いの故障：ページ構造変化（取得成功・解析不能が全件で発生）は即時アラート必須。

### 1-3. 自動返信の形

- チャネル：問い合わせと同一（メール返信）。Mailpitは「受信箱」として残すが、目視確認ゲートは撤去
- テンプレート4種のみ：あり／なし／確認中／サイズ指定あり
- ログ必須：inquiry_id / 照合SKU / 判定 / 返信内容 / 証跡（ページの生テキスト断片）

### 1-4. やらないこと

全カタログ定期クロール、価格スクレイプ、再入荷監視通知、代替商品提案、オーナー承認ゲート、AIによるページ解釈はすべて範囲外。

### 1-5. 検収基準

E2E自動テスト（mock仕入先ページ3種：あり/なし/不明）で「問い合わせIN → 自動返信OUT」までが自動アサーションで完結すること。人的工程ゼロが合格条件。

## 2. 決定2：照合v2（SKU核一致）の確定

### 2-1. 仕様（GLM確定・検収済み扱いの最終形）

1. 正規化：NFKCで半角化 → 大文字化 → 区切り文字（`-` `/` 空白 `.`）を除去
2. 核（コア）抽出：番号が「基地番号＋区切り＋末尾1〜3桁（色コード構造）」なら基地番号を核、それ以外は正規化後の文字列全体を核。両側（問い合わせ側・仕入先側）に同一処理を適用
3. 照合：核の完全一致のみ。曖昧一致（編集距離等）は禁止
4. 名前確認の位置づけ：採用条件ではない。誤照合の検出器としてのみ機能。SKUが一致してもブランド・商品系トークンが矛盾する場合はAUTOにせずVERIFYへ落とす
5. 判定：核一致1件＋名前矛盾なし → AUTO／核一致1件＋名前矛盾 → VERIFY／核一致0件 → NG／同一核で別商品が複数ヒット → VERIFY
6. 色の扱い：採用の可否には関与しない。在庫確認時のバリエーション選択と返信文への記載のみに使用
7. 旧形式27件：正規化＋核抽出で自然に解決する分は回収。残った分はNGのまま集計報告のみ。個別マッピング表は作らない
