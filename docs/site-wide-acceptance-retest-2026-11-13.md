## チャッピー指定の重点5項目

1. **住所情報が欠落せず注文データに保存されること — PASS**
   ⑨で修正済み（mu-plugin nexus-address-guard.php）。本日、注文18916の保存値をDBで再読みした：
   請求先・配送先とも 都道府県=JP26（京都府）、郵便番号=611-0011、市区町村=宇治市、
   住所1=五ケ庄1-2-3、住所2=テスト建物101。町名は欠落していない。
2. **完全な未ログイン状態でゲスト購入ができること — PASS**
   ⑨で実施した注文18916は customer_id=0（本日の読み直しでも確認）。プライベートウィンドウ＋
   合成データ＋メール隔離＋COD一時有効化の条件で確定まで通した。
3. **カートの数量変更・削除とBAG件数が一致すること — 修正のうえPASS**
   当初は不一致を再現した：カート（ブロック）で数量を1→2にすると金額はその場で
   ¥105,400 に更新されるが、ヘッダーの BAG は (1) のまま。行を削除してカートが空になっても
   BAG (1) のままだった。原因は、テーマのヘッダーが件数をサーバー描画のみで持ち、
   ブロックカートの Store API 更新と連動する仕掛けが無かったこと。
   修正：mu-plugin **nexus-bag-sync.php** を新規追加。wc/store/cart ストアを購読し、
   件数の変化に合わせて3か所の表示（PCトップバーの数字 .nexus-pc-topbar__count、
   モバイルホームの .nx-home-bag span、v08ヘッダーの "BAG (n)"）を書き換える。
   再検証：数量1→2で BAG (2)、行削除で BAG (0) に、どちらもリロードなしで即時更新された。
4. **ドロップダウン修正と自動スクロール廃止による回帰不具合がないこと — PASS**
   本日、デスクトップ幅の実タブで MEN'S にフォーカスするとパネルが開き、
   「すべて見る／スニーカー143／フーディー1／ジャケット4／Tシャツ1」が正しく表示された。
   バリエーション選択（色→サイズ→カート追加）も一連の操作が正常で、⑩⑬の数値検証
   （パネル矩形の全幅PASS、スクロール位置不変）は各修正時に完了している。
5. **テスト終了後、決済・通知設定が元の状態に戻っていること — PASS**
   ⑨の復元バックアップ（addr-state-backup.json、10オプション）と現在のDB値を全量照合し、
   全て一致した。COD は enabled=no の値まで一致し、メール9種はオプション行が存在しない
   （＝WooCommerce既定で有効）状態に戻っている。⑨で残っていた verify_identical=NO の
   未確定も、これで「復元済み」と確定できる。
