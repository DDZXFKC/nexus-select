## 1. 完成の定義（全体の完了条件）

以下が全て満たされたとき、仕事の自動化を「完成」と判定する。

1. 確定した対象ショップ全てについて、**商品収集 → データ整備（シート正本）→ 価格検証 → 販売可否判定 → 出品準備（BUYMA）** までが1サイクル実行できる
2. 実行中に人の判断を要するのは §5.4 に列挙した WAIT_OWNER 事項のみである
3. 全過程が記録として残る（report_outbox ／ GitHub ／ シート正本）
4. オーナーの最終検収承認（Phase 6）を得ている

自サイトの最終仕様（海外お取り寄せ）の実装は、オーナー指示どおり**本完成後の別工程**とし、本ロードマップの完走条件には含めない。

## 5. 止まらず完遂する仕組み

### 5.1 即時有効の運用ルール（全AI共通）

- **R1 回収ファースト（最重要・オーナー直接指示に基づく）**: セッション内で次の利用制限までに完了見込みが立たないと判断した時点で新規着手を止め、部分成果を部分コミット＋progressレポートとして残す。**制限ギリギリまで粘らない。** 本書提示時点で即時適用。
- **R2 一作業一報告**： タスク単位で report_outbox に状態を書く。セッション終了時に全体サマリを出す。
- **R3 lease宣言**： 着手時にタスクのleaseを取得（§5.2 未実装の間は指示書ファイルへの着手宣言で代用）。
- **R4 判断の保留**： §5.4 の事項は推測で決めず WAIT_OWNER へ登録する。
- **R5 単一情報源**： 指示・仕様・判定ルールはGitHub上のファイルのみ。チャット完結させない。
- **R6 破壊禁止**： シート正本・ログは消さず隔離する。削除・巻き戻しはGLM検収後のみ。

### 5.2 lease（作業権）

- 保存先： `leases/<task_id>.json`（github_store 経由）。フィールド: `holder, acquired_at, expires_at, heartbeat_at, note`
- TTL: 暫定6時間（適正値は未確定事項#6。運用実績で調整）
- 期限切れ検知： dispatcher が定期チェック → 該当タスクをキューへ戻す → 他AIが再取得可
- 再開時： 前任者の progress レポートを必読してから再開する
- 停止・利用制限・通信断は同型として扱う（heartbeat が途絶＝離席と判定）

### 5.3 report_outbox の運用

- 3種テンプレ: `session_start`（計画）／ `progress`（部分コミット）／ `session_end`（成果＋残）
- progress は「未完の状態」でも出力する。R1 とセットで成果物ロスト防止が目的

### 5.4 WAIT_OWNER（オーナー判断が必要な点はこれだけ）

1. 対象ショップの追加・削除（Phase 4 の範囲）
2. 金銭的閾値の変更（最低利益率・価格下限など）
3. BUYMA への実際の投稿を行うか（デフォルト： 出品データ完成で止める）
4. 既定ルール外の HOLD・判定例外の扱い
5. 本ロードマップ外の仕様変更・新機能追加
6. 各フェーズの完了検収、および Phase 6 の完成宣言

上記以外で判断に迷う場合も、裁量で進めず登録する（R4）。

### 5.5 検収階層

実装者の自己レビュー（GPT）→ コーディネーター検収（GLM）→ オーナー最終承認（WAIT_OWNER#6）。
GLM不在時は GPT が「発行済み指示との照合」のみ行い、検収の追認は GLM 復帰後（Claude はサイト専任のため自動化ラインの検収には組み込まない）。

### 5.6 監視体制と引き継ぎマトリクス

監視：

| 監視対象 | 監視者 | 異常時の動作 |
|---|---|---|
| lease期限切れ・heartbeat途絶 | dispatcher（魔王ちゃんのiMacで定期実行） | タスクをキューへ戻し、記録 |
| report_outbox 長期未更新 | dispatcher（暫定しきい値24h） | 当該AIを離席扱いにし、タスク再割当てまたは待機記録 |
| テスト失敗 | GPT | マージしない。修正してから再提出 |
| 判定ルールの例外ヒット | GPT／GLM | 例外ログを残し保留処理、必要ならWAIT_OWNER |
| シート正本の整合性 | 魔王ちゃん＋GLM検収 | 不整合行を隔離（削除しない） |

引き継ぎ：

| 停止したAI | 影響と継続方法 | 停止中にやってはいけないこと | 復帰時 |
|---|---|---|---|
| GPT | 新規実装停止。既存コードのみ運用し、GLMは仕様・検収を前倒し、魔王ちゃんは実行系を継続 | 仕様の独自解釈による実装 | lease切れタスクから再開。差分をGLMがレビュー |
| GLM | 新規指示・検収停止。GPTは**発行済み指示の範囲のみ**実装し、新判断はWAIT_OWNERへ蓄積。魔王ちゃんは定型実行を継続 | 新仕様の決定、完了宣言 | WAIT_OWNERと経過をレビューし追認または差し戻し |
| 魔王ちゃん | 実行系停止。GPT/GLMはコード・データ・仕様作業を継続し実行キューを貯める | 実行結果の先行記録（未実行分の記載） | キューを先頭から消化、全結果を記録 |
| Claude | サイト作業のみ停止。自動化ラインへの影響なし | — | 従来どおり |
| オーナー | WAIT_OWNER滞留。データ整備・実装・検証は継続し、金銭・公開・仕様変更は全停止 | 承認の先取り | WAIT_OWNERを一括処理 |
