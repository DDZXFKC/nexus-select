# 止まった時の対応ルール（2026-11-14 オーナー提示・優先ルール）

このルールは、通常の進行ルールより優先する。

## 1. 遅延の定義
依頼・通知・引き渡し、または何らかの出力が完了した時点から**5分**経過しても、次のアクションが始まっていない状態を遅延とする。
計測は、出力を終えた側が行う。

## 2. 遅延記録の書き方
遅延を検知した側（GPTまたはGrok）は、該当タスクのメモ欄に以下の形式で追記する。


待つ相手: GPT（または Grok）
必要な行動: （具体的に書く）
対象版: （コミットまたは版）
再開条件: （何が揃えば再開できるか）
記録時刻: YYYY-MM-DD HH:MM

新規タスクは作らない。既存タスクのメモに追記する。

## 3. Museの発見方法
Museは**6分間隔**でリマインダーを確認する。
確認時に検索窓で「」と検索し、ヒットしたタスクをすべて確認する。

## 4. Museが相手を起こす方法
遅延を発見したら、即座に以下を実行する。

① 該当タスクのメモに追記する：
YYYY-MM-DD HH:MM
対象: GPT（または Grok）
指示内容: （何を今すぐやるのかを具体的に書く）

② 同時に以下の優先順位で直接伝える：
- 最優先：GitHubの該当Issueまたは該当コミットにコメントする
- GitHubが使えない場合：合意されたチャット経路に直接書く

③ 実施後、メモに「起動指示済み」と追記する。

## 5. 起動後の確認
起動指示からさらに5分経過しても動きがない場合は、メモに以下を追記する。
起動後も動きなし YYYY-MM-DD HH:MM

この段階でユーザーに判断を求める（メッセージの最後に明示する）。

## 6. 禁止事項
- 遅延記録をリマインダーのメモ以外にしか残さないこと
- Museが「」を検索確認せずに通過すること
- 起動指示を片方の経路だけで終わらせること
- ユーザーを伝言役にすること

## 7. 優先順位
1. 5分経ったら遅延記録を書く
2. Museが発見したら必ず起こす
3. 起こしても動かない場合のみユーザー判断に上げる
4. その間も独立して進められる他のタスクは止めない
