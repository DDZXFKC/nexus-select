# SP の紐付け：サイト側サイズ別 SKU ＝ Shoe Palace の variant SKU（Claude 実測、2026-11-21 19:03 JST）

オーナー指示「そうと仮定して試してみよか」による確認。読み取りのみで、データは何も変更していない。

## 結果
- XServer の SP 商品について、サイズ別データ（Woo の variation）の SKU を調べた。1,713 件すべてが数字だけで、重複は 0 件。
- 7 商品・77 件を突き合わせた。
  - 対象：21376、19905、19947、19854、19812、19801、20043。
  - 方法：Shoe Palace の公式 `/products/<handle>.js` にある `variants[].sku` と、Woo の variation SKU を比べた。
- **SKU だけで 77 件すべてが 1 対 1 で一致した。** 見つからないもの 0 件、ずれ 0 件。
- 確認のため、一致した組のサイズ表記も比べた。Woo の「US 」と「(…cm)」を外した値と、Shoe Palace の option1 は 77 件すべて同じだった。
  - 子供用の 3Y・4Y・5Y・6Y も同じく一致した。
- 例（Vans 21376）：US 5 → 21141139 ＝ SP のサイズ 5 の sku 21141139。
  - 10〜11 は 21141124〜26 で、番号が連続していない。それでも一致した。

## 意味
- Local の取り込み時点で、Shoe Palace のサイズ別 SKU は Woo の variation SKU にそのまま保存されていた。
- **紐付けの鍵は「親 SKU（SP-<Shopify 商品ID>）＋ variation SKU（= Shopify の variant SKU）」でよい。**
  - サイズの文字を比べる必要はない。「US」、cm、子供用の規則は、照合には不要。
- 元データは書き換えない。この鍵は、取り込み時から保存されている値をそのまま使うもの。
