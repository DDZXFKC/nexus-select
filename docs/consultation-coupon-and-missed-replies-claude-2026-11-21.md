# 相談への Claude 案：クーポン完成と見落とし防止（2026-11-21）

相談元：docs/consultation-coupon-and-missed-replies-2026-11-21.md。GPT 案を読む前に、独立して書いた。GPT 案との比較は、魔王ちゃん・オーナー側で行ってください。

## 問い1：クーポン

### 結論
- 「実際に効いた証拠がないと使わない」という今の条件は、**価格計算の前提条件からは外す**。シートの条件で判定し、割引を入れて原価を計算する（オーナー決定どおり）。
- 実際に効くかの確認は**全面廃止ではなく、後から確かめる役に回す**。確かめ方は次の2つだけにする。
  - **クーポンごとに1回だけの確認**（商品ごとではない）：
    - 魔王ちゃんがカゴで1回効くことを確かめたら、シートの「状態」を「有効」にし、「最終確認日」を入れる。
    - 効かなかったら「無効」にする。
  - **実際の買い付けの結果**：
    - 買い付けのたびに、カゴで効いたかどうかが分かる。
    - 効かなかったら、そのクーポンの「状態」を「無効」に変える。そのクーポンを前提にした価格は計算し直す。

### 理由（反対意見も含む）
- 証拠必須のままでは、原価が永久に決まらない。これは今起きていることのとおり。
- ただし、効かないクーポンを前提に値付けすると、その商品は赤字になり得る。
  - 例：利益率16%に対して、20%オフが効かなければ赤字。
  - なので「要確認」のままのクーポンを価格に入れるかどうかは、**オーナーに一度だけ決めてほしい**。
    - A：「有効」になったものだけ入れる（安全。最初の確認は約7件で済む）
    - B：「要確認」も入れる（速い。外れたら赤字の可能性）

### やること（最小・この順番で）
1. **シートの条件で判定する経路を足す**（GPT）
   - 「クーポン管理」タブの行を読む。
   - 店・有効期限・利用条件・除外条件が商品に合い、状態が条件を満たすものを、割引として原価に入れる。
   - 既存の判定（`evaluate_eligibility`）に、シート由来の行を渡す形にする。
   - 「実測がないと使わない」安全チェックは、この経路では使わない。
   - 価格には「クーポン前提（実測前）」の印を付けて、後で区別できるようにする。
2. **約7件のクーポンを1回ずつ確認**（魔王ちゃん）。A を選んだ場合だけ要る。
3. **メルマガからの収集**（GPT＋魔王ちゃん）
   - 1日1回、接続中の Gmail で、登録済みの店から届いたメールのうち「code / % off / クーポン」を含むものを一覧にする。
   - 魔王ちゃんがシートに「要確認」で登録する。
   - 文面の自動解釈まではしない。一覧が出れば足りる。
4. **古い経路は統合せずに止める**（GPT）
   - ahc-system 側の coupons/collector.py と buying/coupon_applier.py は、呼ばれたら止まるようにする。
   - 経路を bridge 1本にする。
   - 統合は、必要になってからでよい。
- テストは、1 の新しい経路の数件だけ足す。
  - 有効なら割引が入る
  - 期限切れ・除外・無効なら入らない
  - 印が付く

## 問い2：見落とし防止

### 結論：「受信台帳」を1つ作り、そこへの記入を完了条件にする
- **置き場所**：既存の作業ボードかシートに1タブ。
- **項目**：到着日時、経路（メール／BUYMA／ライトハウス／Locanto／Tomo's list など）、相手、要点1行、返事が要るか、下書きの場所、オーナーへ伝えた日時、状態。
- **完了の定義**：「オーナーへ伝えた日時」が埋まった行だけが完了。「届いた」の確認だけでは未完了のまま残る。

### 既存の仕組みに足すもの（最小）
- **30分ごとのリマインダー監視**
  - 対象に「台帳で未完了のまま2時間たった行」を足す。
  - これで魔王ちゃん側の仕事も見張られる。
- **日次報告**
  - 「今日届いたもの」の節を足し、台帳の新しい行の要点をそのまま載せる。これがオーナーへの伝達になる。
  - 「見落としなし」と書いてよいのは、次の2つが揃ったときだけ。
    - 経路ごとに「何時に確認して何件」を書いた
    - その件数が台帳と合っている
- **サイト内受信箱**（メール通知が来ない掲示板）
  - 日次確認の手順に「各掲示板にログインして受信箱を見る」を明記する。
  - 0件でも「確認済み・0件」を台帳に1行残す。確認したことの証拠になる。
- **Gmail**
  - サポート窓口・掲示板・BUYMA からのメールにラベルを付ける設定を入れる。
  - ラベル付きの未読が残っていたら、30分監視で知らせる。
- **作業ボード監視（15分）**は変えなくてよい。

## 相違点の確認用（Claude 案の要点）
- クーポン

  - 確認はクーポン単位で1回。商品単位ではない。
  - 「要確認」を価格に入れるかは、オーナーが A か B かを決める。
  - 古い経路は止めるだけで、統合はしない。
  - メルマガは一覧を出すまで。

  - 受信台帳を作り、「オーナーへ伝えた日時」の記入を完了条件にする。
  - 「見落としなし」は、経路ごとの件数を書いたときだけ書ける。
