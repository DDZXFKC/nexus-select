# クーポン収集をどのPythonに組み込むか：GPT独立案（2026-11-17）
結論：収集は独立モジュール/独立実行、適用判定は商品収集・売れ筋発掘・買付時で共有する。既存の商品収集と売れ筋発掘の合意を変更しない。3者合意前の提案。
## 根拠
オーナー決定 docs/catalog-import-owner-decisions-2026-11-16.md：原価は適用可能なクーポン込み、条件は仕入先別に保存。最終出力は採用店と代替店、自サイト価格はBUYMA売価からBUYMA手数料額を差し引く。
実コードを確認：ahc-system/src/ahc/coupons/collector.py、validator.py、buying/coupon_applier.py、collector/ahc_collect.py。既存収集はsource単位の例外隔離・DB upsertを実装、validatorは期限（日単位）とブランド/最低額/初回を判定、配送地域は未判定でもTrueを返す。現行applierはライブカート操作・試行記録。これらは再利用候補だが、実店舗稼働は未検証。collectorのstore未解決NULL、code/sourceの重複、再取得時の状態上書き、日時精度、applierのstore/code検索で複数sourceが一致する可能性、例外時のrollback、未実装adapterを要検査。既存ahc_collect.pyは初回variant代表・INSERT OR IGNOREで価格更新を保証しないためクーポン機能追加前に既定の欠陥修正を優先。別システムのDBをそのまま正本にしない。
## 分担
1. クーポン収集：既存 coupons パッケージを調査し再利用できる部分だけ、独立CLI（例 coupon refresh）へ。店公式プロモーション/許可された配信・フィード、次に許可済みクーポン情報源、手動入力。店別アダプター。外部サイトのコードは未検証候補。自動値引き（コード不要）も別種別で保存、セール価格と二重控除しない。
2. 商品収集 ahc_collect：商品・サイズ・通常価格/セール価格・在庫の店別観測を保存、共通クーポン判定を呼びL2条件/L3採用店/原価計算へ。クーポン取得失敗で商品収集を止めない。既知の値を消さない。クーポン検索を全商品ごとに実行しない。
3. 売れ筋発掘：trend_items.dbは順位/発掘根拠の正本、店別クーポン正本を読み取り利用。入口の人気順位を割引で変えない。出口で適用後原価/利益、競合価格、代替店を比較。クーポン発見から割安商品を逆引きする発掘経路は将来候補。未検証でも発掘候補は保存。
4. 買付：注文前/買付前に対象サイズ・数量・アカウント・配送先・期限で再確認。許可された方法だけ。実際の決済・注文は別承認。クーポンを調べるだけでカートを大量に作らない。購入自動化を開始しない。
## 保存
iMac既存L2店別条件SQLiteにcoupon_rules / coupon_observations / coupon_checks（既存schemaに合わせる）を持つ。1つの正本、店ID・地域/通貨・コード/自動割引・割引種別/値・対象/除外ブランド・商品/variant・カテゴリ・最低金額/数量・上限・初回/会員・利用回数・配送先・併用・開始終了時刻とtimezone・根拠URL/取得時刻/確認者・確認結果と対象条件。出典履歴と適用判定履歴を分離。別店に同じコードがあっても混同しない。個人専用コードや認証情報を公開しない。trend_items.dbは参照ID/観測時点の計算スナップショットのみ。Sheetsは派生ビュー。既存価格・在庫を勝手に変更しない。
## 判定
DISCOVERED（候補）、CONDITIONS_CONFIRMED（条件根拠あり）、APPLICABLE（対象条件が確認済み）、NOT_APPLICABLE、UNKNOWN、EXPIRED。実カート適用確認は対象アカウント/variant/数量/配送地域/時刻に紐付け、全商品永久有効と扱わない。期限不明・条件不明・第三者サイトのみ・初回資格不明・地域未確認は割引を確定原価に使わない。公式条件で適用が確定できる範囲のみ、オーナー方針どおり割引後原価を基本にする。通常原価と割引原価を両方保存。失効時は通常価格または代替店で再計算、履行不可なら新規販売停止、成立注文の追加請求なし。クーポン依存だけで一律HOLDにしない。税・送料・関税・手数料等は全費目計算。
## 起動・頻度
通常STARTでクーポン更新（鮮度不足の店のみ）→商品収集または売れ筋発掘→判定→出力。クーポンのみSTART/再計算のみも可能。独立処理なので商品全取得不要。初期は手動起動実機合格、後に日次更新案（在庫週2回とは別、許可範囲・予算に従う）、期限切れはローカル時計で判定し都度再計算。注文前再確認。AIランタイム0、ログ/チェックポイント/排他/失敗隔離。取得禁止/403/429は既定ルール、回避なし。
## MVP
既存保存済みクーポン/公式条件の証拠1店と実商品データ数点で、適用・対象外・期限切れ・初回/地域不明・自動セール二重控除・最低額/数量・併用・同コード別店・失効再計算をオフライン検証。正本保存と両Pythonの同一結果、再起動・冪等・ログ確認。許可済み1店で手動STARTから実際の新規クーポン情報を取得・保存・計算する試験は別段階。実績がなければ未達とする。クーポン収集のために全商品を取り直さない、購入や公開なし。既存収集の完成を遅らせず、独立モジュールを並行開発。Claude/GLMの意見を待って共同仕様に合意する。
