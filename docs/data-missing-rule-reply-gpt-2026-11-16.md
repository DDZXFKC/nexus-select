# 商品情報欠落・取得方式の一般ルール（GPT独立案）
2026-11-16。相談 docs/data-missing-rule-consult-2026-11-16.md、owner-decisions、統合preflight v2、Claude import risks を確認。今回のUGG修正は対象外。合意・実装・公開承認ではない。Shoe Palace実行Python・保存原本・UGG公式取得証拠は公開ブランチで確認できず、原因は未確定。既存の店別Python/SQLite/派生Sheetsを維持し、新規システムは作らない。GLMは今回相談のレビュー担当としてのみ扱う。
## 1. 原則
収集・保存・下書き・公開は別。欠落でも収集保存、既知の正常商品を継続。安全に識別できるもののみdraft。必須の欠落1件で当該商品/variantの購入不可。欠落総数だけで全体停止しない。共通抽出/価格/識別/出力の破損、全件異常、権限違反、既存商品破壊など波及原因は影響範囲を隔離し公開停止。未知をゼロ/在庫なしと扱わない。必須情報を推測で埋めない。オーナー承認ルールを維持。
## 2. 項目別の公開ゲート
- 商品同一性（店ID、メーカー品番または確認できる代替同一性、ブランド、色、商品名、仕様差、対象）、カテゴリ既存91分類、元URL、正当な販売/画像利用条件：不確実なら親単位HOLD。メーカー品番なしでも店IDで収集可、他店統合不可、本人確認の代替証拠で公開判定。SKUは既存の安定IDを維持。
- 価格/通貨/適用条件の確認できたクーポン・税・送料・代行・為替等必要原価/売価、在庫/サイズ原表記/サイズ体系、配送可否：欠落したvariantを販売不可。親は他の適格variantがあれば公開候補。全variant不適格ならHOLD。既存公開商品は購入不可に切り替える（表示/非表示は確定方針に従う）。週2回在庫同期、注文時再確認。失敗で過去値を上書きせず鮮度切れは販売停止。通常価格と割引価格・期限を保存。自サイト=BUYMA価格-販売手数料額の確定方針維持。
- KIDS US+cm併記はオーナー確定の必須表示。公式JP/CMを対象ブランド・年齢・性別・モデル・サイズ体系に合わせる。公式にない場合はNULL/NOT_PUBLISHED。次回以降はそのvariantを公開保留（他サイズは公開候補）、元サイズだけ表示する例外は3者合意/オーナー承認が必要。今回の8件は修正対象外。US1C等を別ブランド表で換算しない、足長/靴内寸/JP表記は別の値。現物実測は測定方法付き実寸であり公式換算ではない。注文後入手する無在庫商品では購入前の必須情報を到着後測定で代替不可。
- 素材/仕様：法令・商品安全・アレルギー・品質表示上必要な場合、または仕様同一性/購入判断に不可欠ならHOLD。その他は未記載で公開候補、虚偽説明なし。日本の繊維製品品質表示等の適用を別途確認。説明文は事実に基づく独自文、販促コピーは可だが素材/性能/希少性の創作禁止。
- 画像：当該色の正確なメイン画像、利用根拠、既存白背景正方形・輪郭品質、表示成功は必須。追加画像不足は記録し、必須枚数は既存ルールに従う。違う色や他モデル画像で代用不可。
- 人気順位、国内希少性、発売日、追加説明、補助画像等は一般収集の任意情報（出品/販促で主張する場合は証拠必須）。リサーチと公開承認を区別。需要の推測は仮説としてのみ記録。
## 3. 欠落ステータスと証拠
項目値とは別に field_status=OBSERVED/VERIFIED/NOT_PUBLISHED/NOT_APPLICABLE/NOT_FETCHED/PARSE_FAILED/ACCESS_BLOCKED/CONFLICT/STALE。取得元URL・店ID/variant・取得日時・source type・script/version・元フィールド/selector・原本hash・試行結果を保存。公式に載っていないことは対象ガイド確認後のみNOT_PUBLISHED。アクセス不能と情報不存在を区別。店別DBの既存schemaに合わせ最小差分、原本不変、正本は店別。Google Sheetsに欠落一覧と取得手段を派生出力。手動値にも証拠を要求。
## 4. スクレイピング見直し（最重要）
まず実際のShoe Palaceコード/保存原本/CSV/投入後データを同一IDで比較し、8件が元から不存在、抽出漏れ、変換漏れ、投入漏れのどれか特定する。公式ガイドにないという報告は検証対象。今回公開済み商品の修正はしない。原因確認のための保存原本調査は可。
各店の取得許可を事前確認。許可済み公式フィード/API→保存HTML/商品ページの構造化データ(JSON-LD、埋込JSON、公開variantデータ)→DOM本文/サイズ表→公式ブランドのモデル別/年齢別ガイド→正規店の同一品番情報→人の確認・問い合わせの順。順序は情報項目別。店の在庫・価格は当該店舗のvariant証拠のみ、他店の値で補完不可。メーカーの素材/仕様は同一品番・カラー・地域仕様で照合。日本発売/希少性は国内公式・SNEAKERWARS等を別証拠として保存。画像は同一色の公式ギャラリーから全利用可能URLを保存、利用許諾と分離。検索スニペットは探索のみ、最終証拠不可。
各店Pythonの初回取得時に許可範囲の情報をまとめて抽出。欠落のために全ページを再取得しない。保存原本を再解析し、取れていない項目だけの補完キューを作る。ブランドサイズ表はブランド×対象×製品種×地域×版/取得日でキャッシュし、多数商品に再利用、対応不確実なら適用しない。各店順次実行の単一CLI、独立失敗継続。429/403/規約拒否は停止・記録、制限回避禁止。通信一時エラーのみ許可予算内の上限付き再試行。不存在は無限再試行しない。更新条件（公式変更、新規証拠、期限）まで保留。既存のfetch_products.py等を再利用、実物確認まで修正開始と主張しない。
## 5. チェックの実装
L0 raw→L1 店別抽出→L2 補完/条件→L3 出力比較→L4 draft/公開前QA。各段階の同一IDと件数を突合。対象カテゴリ別required schema、null/空文字/ダミー0/通貨・桁・サイズ体系・重複・variant整合・画像色・根拠鮮度を機械検査。値が埋まるだけで合格にしない。全件dry-run、保存原本の正常/欠落/競合/乳児サイズ/衣類/複数店/在庫変動の代表fixtureで差分検証。既存公開を守る。投入後readbackで親/variant/表示/購入可否を照合。全件自動検査＋代表目視。補完できた情報のみ更新、失敗で既知値を消さない。元表記と表示表記を別保存しSKU変更を避ける。
## 6. 報告
店別に発見数/取得数/ユニーク親数/variant数/必須欠落親・variant数/任意欠落数/補完成功/未解決/公開可能/下書きのみ/失敗を区別。項目別欠落率=欠落対象数÷適用対象数（N/A除外）、原因別集計、前回比較。1商品複数欠落は重複計上の説明。例外一覧ID・項目・理由・取得手段・証拠・次の処理・担当。未取得理由のみ報告して終わらず、取得できる補完を一括処理。件数ゼロも明示。全体合格と部分合格を区別。
