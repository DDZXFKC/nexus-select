## 1. 横断CSVインターフェース v1（a3789459）→ 条件付き承認

### (a) サイズ別採用判定について — 最終判断

**v1はカラーウェア単位（横断キーと同一粒度）で採用を確定し、サイズ別採用は行わない。** この判断でGPTの設計ゲートはクローズ。

理由：
- 横断キー＝ブランド＋型番＋色コードなら、グループの同一性と採用の粒度を一致させるのが契約として最も単純。サイズ単位に分割すると1グループから複数ショップの行が継ぎ合わされた複合レコードが生じ、原価の出所管理が複雑化する。
- オーナー決定により在庫は判定に使わず受注・購入時点で確認する設計なので、静的インターフェースにサイズ別最適化を組み込んでも設計上すぐ陈腐化する。購入時の再評価が本来の制御点であり、在庫方針と同じ制御点に置くのが一貫している。
- 「資格ある候補が無ければグループHOLD」の意味論もグループ単位で定義済み。サイズ単位採用はHOLD条件の再定義を要求する。

ただし既知の限界として明記すること：**採用元が全サイズで最小価格とは限らない。サイズ別の最終判断は購入時点で行う。**

### 契約反映条件（実装着手前）

1. **採用元のサイズ別価格・stock_observed は観測列として全件出力に残す**こと。加えて候補間でサイズ価格に乖離がある場合のフラグ列（例： `size_price_divergent`）を1つ追加。順位には影響させず情報は落とさない。stock_observed には観測時刻の出所をスキーマに明記（後から誰も権威扱いしないため）。
2. **仕入総額の原価基準の粒度を明記**：ロット単位（カラーウェア単位）かサイズ単位か。
   - ロット単位なら現行の比較はそのまま成立。
   - サイズ単位の総額が載る場合、サイズ構成が異なる候補間の総額比較は不当になるため、比較キーを「共通サイズ上のサイズ別原価」に再定義するか、v2でサイズ単位採用に分割。**ここが未確定なら実装着手不可**（唯一デザインを変え得る条件）。
3. **資格定義の厳密化**。「原価未計算は資格なし」と「検証済み仕入総額の最小」の関係が曖昧。原価計算済みだが総額未検証の候補に資格はあるのか。資格＝「原価計算済み かつ 仕入総額検証済み」と一行で定義すること。現状では順位チェーン3番目の「原価計算済みフラグ」は資格定義と重複し常に真＝実質デッドコード。防御として残すなら注記を。
4. **HOLD理由コード**を候補ごとに出力（cost_uncalculated / total_unverified 等）。原価計算作業の優先順位付けに使える。
5. **正規化のフィクスチャ化**。ブランド正規化（表記ゆれ・全角半角・商標記号）、色コード形式（前置ゼロ・区切り・大小文字）。横断キーは偽陰性（マッチ漏れ→グループ分裂）が主リスク。FL/SP既存CSV→source offer input v1 の変換器には往復テストとキー重複監査を必須に。※FL確認リスト6項目の結果はこの変換器フィクスチャに反映させること。
6. タイブレーク最終段の安定行IDは良い判断（冪等性保証）。ID導出規則は文書化。

## 2. バッチ3 E-1再発防止計画（efb05470）→ 条件付き承認

方向性は正しい：未知はHOLDで停止（フェイルクローズド）、プリフライト成果物の独立出力、既知事故の回帰フィクスチャ、SKU例外→型番辞書→デフォルトの特異度順序。バッチ3を横断統合を待たずに進める位置づけも承認。

### 前提条件（生成開始前）

1. **SPプールのスナップショット固定**。プールは158→163へ更新中。バッチ3生成は確定済み163件スナップショット（リストハッシュ）を参照し、マニフェストに記録。更新中の動く対象を直接参照しない。復帰する**Vans 5件もカテゴリ証拠必須対象に含める**。
2. **プリフライトはハードゲートとして機械強制**（exit 0 を生成の前提条件。助言でなく）。
3. **否定経路のフィクスチャ追加**。正解割当（Tasman/Neumel等7件）だけでなく、(i) 未知SKU→HOLD→生成停止、 裏切り検出→HOLD、 ブランド×部門デフォルト適用不可→HOLD、の最低3系統。フェイルクローズド機構自体の回帰テストが最も効く。

### 実装要求（設計変更なし）

4. **マニフェストに判定経路を記録**：各アイテムがどのルールで決定されたか（exception_map / dictionary / brand_dept_default）を1列で。再発時に即座に切り分け可能。
5. **「全件同カテゴリ確認」の維持機構**：確認根拠（確認日・対象件数）をデフォルト表に持ち、同ブランド×部門の件数が増えたら自動失効→再確認要。壊れやすい不変条件には明示的な失効トリガを。
6. **HOLD解消の還元ループ**：解消結果を例外マップ/辞書へ反映し、同一SKUが二度HOLDしない経路を定義。無いとHOLDが量産される。
7. マニフェストの再現性項目：例外マップ/辞書のバージョン、プリフライト版、プールスナップショットID、フィクスチャ全pass記録。

**過剰箇所は特になし。** 矛盾検出をスリッパ/サンダル×ブーツ以外に拡張するのは実際の混同事例が増えてからでよい。
