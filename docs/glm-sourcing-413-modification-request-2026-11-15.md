# AFTER HOURS CLUB｜商品発掘・収集システム 413点対応改修依頼書（正式版）
確定日：2026-11-15。宛先：GLM（改修担当）。実行：魔王ちゃん。監査：GPT。技術支援：Claude。最終承認：オーナー。
本書は魔王ちゃんが共有した依頼書の要点と確定した3点の修正、413点の機密保持条件、最新参照監査を統合した正式な改修仕様。11/14のGPT開発引き継ぎ方針に優先する。
## 1. 目的・担当・範囲
主に海外、一部国内の日本市場で販売価値のあるアパレルを発掘・収集し、買付先、サイズ別価格・在庫と、同一商品のBUYMA等の参考価格を確認できるようにする。413点は今回の確認対象リストであり、候補発掘の範囲を413点や特定ブランドに恒久限定しない。
GLMは既存Pythonコードの改修・単体テストの作成と納品のみ担当。GLM環境での本番処理・ライブアクセス・413点の実行は行わない。魔王ちゃんがiMacで実行・検証する。実サイト不要のfixtureベース単体テストを納品し、実行結果を捏造しない。WordPress/WooCommerceへの書き込み、自動出品・買付・決済・発送、ECサイトの改修は対象外。
## 2. 413点正本の機密保持（厳守）
- 413点の正本は魔王ちゃんの管理下に置き、GLM・公開GitHub・外部サービスに出さない。対象リストを外部入力ファイル（ローカルのパス指定）として読み込む。コードに埋め込まない。
- GLMに渡すのはヘッダー定義と機密情報を除いたサンプルだけ。サンプルは魔王ちゃんが用意済み。ヘッダーとサンプルの実物を正として列の意味を確認する。ここでは未受領の列名・内容・ファイル形式を推測で決めない。
- 正本、実行結果、手動価格、承認ファイル、認証情報、未公開仕入情報を外部送信しない。ログも必要最小限。テストは匿名化/合成データのみ。GitHubに登録するのは公開可能なコード・仕様・匿名化集計のみ。
## 3. サイズ別展開・データ保全
- 出力は商品×カラー×サイズ（サイズ体系も明示）で1行。複数買付先は同一候補に対する別オファーとして保持。重複を抑制し、元リストの全413点を処理済み/保留/失敗のいずれかで追跡可能にする。展開後の行数は413と一致する必要はない。
- ブランド・品番・カラー・サイズ体系・サイズ・新品/中古状態を証拠に照合。取得元の商品URL、取得日時（TZ付き）、通貨、価格、サイズ別在庫を保存。未確認の内部値はnull（CSV表示は不明可）、在庫UNKNOWN等。SKU、カラー、サイズを推測で生成しない。サイズ展開不能でも候補の保留行を保持し、取得失敗を在庫なしと混同しない。
- 候補発掘・候補保存は他店の参照価格がなくても継続する。
## 4. 仕入価格と参考価格・同一性
- 価格の観測状態（OBSERVED/ESTIMATED/UNKNOWN等）と価格の役割（PURCHASE_OFFER/ASK/COMPLETED_SALE等）を別軸にする。実測出品価格は実測仕入価格ではない。サイズ不明の代表価格、出品価格、成約価格、送料関税込みの価格を混同しない。
- BUYMA/SNKRDUNKの検索結果はブランド、品番、カラー、サイズ体系・サイズ、状態、コラボ/仕様で厳密照合。検索ページから無関係な結果や他カラーを採用しない。品番不明は候補として保存できるが検証済み価格にはしない。検索URLだけではなく個別商品/出品/取引URL、価格種別、確認日時、サイズ、出品/成約等の証拠を記録。検索失敗/未確認/該当なしを分離する。
- 国内外の参考出品価格は人の価格判断用に表示してよいが、成約と混同しない。他店価格から仕入価格を逆算/代替しない。想定価格を実測仕入・確定利益に使わない。参照全体の最高値で差額を計算する処理と「検証済み(自動)」表示を廃止する。
- 403・接続失敗時は記録して次に進む。プロキシ等による制限回避は行わない。許可された正規取扱店を候補として利用し、取得不可なら手動確認を取り込む manual_prices.csv の入口を用意。手動価格にも対象識別、買付先URL、通貨、サイズ、確認日時、状態、在庫の根拠を必須とし、証拠が揃わなければHOLD。
## 5. 承認と利益監査
既存の research/online/local-pkg/sourcing_gate.py（stage2_review.py依存）を再利用するか、同一入力形式への変換を提供する。既存ゲートを書き換えて緩和しない。
- 入力は候補単位の candidate / offers / references / cost_inputs。IDENTITY = brand, style_code, color_code, size_system, size, condition。欠損はnullとし、「不明」「—」等を有効な識別子として渡さない。
- 検証済み仕入は同一identity、OBSERVED、HTTPS個別URL、TZ付きchecked_at（既存ゲート24h以内）、PURCHASE_OFFER、seller_verified=true、stock=IN_STOCK、stock_verified=true、対応通貨、offer_idによる明示的選択を満たす。フラグを検索成功だけで真にしない。
- 参考は同一identity、OBSERVED、JPY、ASKまたはCOMPLETED_SALE、reference_idと個別URL、日時。出品/成約を分離。既存ゲートが成約根拠不足でHOLDとしても候補・参考出品価格は残す。
- 原価は実測仕入、為替、現地税、国際送料、関税、輸入消費税、代行費、国内送料、決済/販売手数料等の必要費用を明示し二重計上しない。不明費用をゼロ扱いしない。既存gateのcost_inputsに対応する根拠を提供する。実測価格・必要費用・販売価格シナリオの根拠不足時は利益null/HOLD。確定利益ではなく検証済み条件下の見込み利益と表示する。
- 全行初期HOLD。既存sourcing_gate.pyはreview_readyを判定するが自動承認しない（decision=HOLD、approved_for_import=false）。人の明示的承認ファイルのみを別工程で反映し、必須検証を通過していない行は承認入力があってもHOLD。承認対象は安定した候補・カラー・サイズ・オファーの識別子と証拠に紐付け、価格・在庫・証拠の変更/期限切れ後に旧承認を流用しない。approvedは自動出品・購入を意味しない。
