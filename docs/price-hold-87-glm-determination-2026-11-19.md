## 3. データ受領後に適用する判定ロジック（固定版）

以下を本書で固定します。受領データに対し、この決定的ルールを Python で一括適用します（人手判定・恣意的解釈の不入り）。

```
分類ルール（各バリアント、世代別の最新観測 old / new に対して）：

1. old または new の観測が存在しない      → INSUFFICIENT_DATA（確定不可）
2. old.price == new.price                 → NO_DIFF（差異消失。HOLD解除候補）
3. old.observed_at 〜 new.observed_at の間に
   仕入先ページの価格改定が観測されている    → PRICE_CHANGE（観測時刻の差＝価格改定）
4. 同一時刻帯の観測なのに価格が異なり、かつ
   variant_key（サイズ等）のマッピングが重複・欠落 → MAPPING_ERROR（マッピング誤り）
5. 上記いずれも該当せず、生ページ再取得価格が
   new.price と一致                        → PRICE_CHANGE_CONFIRMED_LIVE
6. その他                                  → UNRESOLVED（その他・確定不可）
```

```python
def classify(v, events, mapping):
    old, new = v.old_obs, v.new_obs
    if old is None or new is None:
        return "INSUFFICIENT_DATA"          # 確定不可
    if old.price_usd == new.price_usd:
        return "NO_DIFF"
    if events.between(old.observed_at, new.observed_at, v.product_id):
        return "PRICE_CHANGE"
    if mapping.is_ambiguous(v.variant_key):
        return "MAPPING_ERROR"
    return "UNRESOLVED"                     # 確定不可
```

**正本反映の可否ルール（これも固定）：**

- 反映を許すのは **`PRICE_CHANGE_CONFIRMED_LIVE` のみ**。すなわち「仕入先の生ページを再取得し、その価格が新世代観測値と一致した場合」だけ。capture_hash を証跡として添付して正本価格（USD仕入価格）に書き込む。
- `PRICE_CHANGE`（ログ上のみ一致、生確認なし）は「原因は確定、正本反映は保留」。
- `MAPPING_ERROR` は原因確定後、マッピング修正 → 再照合を経てから反映。価格の直接上書きはしない。
- `INSUFFICIENT_DATA` / `UNRESOLVED` は **HOLD 維持、コスト計算から除外しない（ゼロ扱い禁止）**。
