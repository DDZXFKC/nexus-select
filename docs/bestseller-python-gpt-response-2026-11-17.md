# 売れ筋商品発掘Python：GPT第1ラウンド（2026-11-17）
根拠: ccc9a2a691e52ee7a578bf604aa3a90eb04918dc の審議開始文書。独立提案であり3者合意ではない。魔王ちゃんは運搬のみ。
## 1. 結論・対象店舗
オーナーの「各店舗を回って集計」に賛成。ただし店の全商品を取得するのではなく、店が提示する売れ筋候補を集める入口と、日本で販売する価値を判定する出口を分離する。海外人気と日本での売れ行きは同義ではない。発掘先と買付先も同一である必要はない。
既存資産のNotreベストセラー342点を第1試験の入力候補、Foot Locker/Converseのrating-top48等を別信号の入力候補とする（実ファイル・列・取得日・並び順根拠は未取得、審議文書の報告ベース）。Notreのベストセラーが実売数順かは確認する。Foot Locker/Converseの評価順は評価順と記録し、販売数順に読み替えない。自動収集禁止の店は許諾済みフィード/公式提供情報/利用可能な既存データ等の適法な入口を使い、自動取得を強行しない。オーナー指示は第三者規約・アクセス制限の許諾に代わらない。
候補拡張はKith/Patta/BSTN等の公開ベストセラー・人気順・新着・限定情報を店別に実物確認し、利用可能な信号のみ登録する。店名だけで売れ筋信号があると断定しない。対象は靴・服・帽子・バッグ・アクセサリー等全般。日本未発売/海外限定/国内完売/サイズ欠け/海外仕様/価格優位も独立した発掘信号。日本の売れ筋・発売情報・需要のあるブランドやモデルから海外の買付先を逆引きする入口も持つ。初期実装で全入口を完成させる必要はない。
## 2. 回り方・集計・順位
単一手動CLIから店別アダプターを順番に実行。店別に性別/末端カテゴリ/信号を指定し、上位N（初期試験20程度、実際の上限は承認・規約・実測で決定）だけ取得。既存CSV/Sheets読み取りもアダプターにする。各信号の名称・順位・母集団・件数・取得日時・URL・根拠を保存。実売順位、ベストセラー表示、評価点、レビュー件数、在庫変化、SNS/新作は区別。レビュー高評価を実売とみなさず、在庫欠け単独も人気と断定しない。売れ筋の根拠がなければ不明。順位を店間で単純平均しない。
順位はまず店×カテゴリ×信号の中で保持し、横断比較は同種の根拠のみ、異種は別列。候補の優先度は(1)国内需要/希少性の証拠(2)海外売れ筋信号の質/順位/鮮度(3)買付可能性(4)原価と価格競争力。初期は根拠付き分類・並べ替えで十分。任意の重みを確定仕様にせず、実際の販売結果から後で調整。競合販売がない商品も候補として残し、検索失敗と該当なしを区別する。
処理順：発掘候補リスト→同商品が買える店の調査→国内競合販売価格収集→買付条件比較→原価/利益検証→出品候補。候補発掘は価格参照不足で破棄しない。最終出品可否は別ゲート。BUYMA/SNKRDUNK等は品番/カラー/サイズ/仕様/状態を照合、出品価格と成約価格別、推測価格を実測扱いしない。
店別原本・観測を独立保存。最終出力段階で確実なメーカー品番・カラー・仕様の一致を判定し重複抑制、サイズ別の仕入先と代替仕入先を保持。曖昧一致は要確認。価格だけでなく在庫・配送・返品・適用クーポンを含む実原価で選定。オーナー決定のクーポン基本適用、BUYMA販売手数料差分の自サイト価格方針を維持。通常原価と失効時の再判定も保存。既存SKU/出品を勝手に変えない。
## 3. 保存
既定のSQLite正本、店別観測/信号/候補/買付先/競合参照/原価/判定runを段階保存。店別原本不変・hash・取得時刻、出力決定IDで一意。CSV/Sheetsは確認用派生。出力列: 商品/品番/色/カテゴリ/サイズ、発掘根拠と順位、国内状況、買付店・代替店・在庫、通常/クーポン価格、競合価格種別、利益、確認時刻、HOLD理由。全候補と出品可能分は別出力。既存stage3 SQLite資産を現物照合して再利用し、カタログ収集ahc_collect.pyと発掘ロジックは分ける。
## 4. 実行
iMacの信頼できる手動STARTから単一CLI。ネットワーク/認証に依存しない既存ファイル取込を先行。店/カテゴリ/信号別のキュー、run_id、DB成功後チェックポイント、排他ロック、途中停止後再開、同一入力の冪等、価格在庫更新履歴、取得失敗と売切れの区別。429はRetry-Afterに従い停止/許可された範囲の再試行、403/自動収集禁止は停止して他店を続行。VPN/IP切替でアクセス制限を回避しない。許可済み取得方法の見直しを行う。実際の購入/出品なし。
## 5. 最小試験
まずNotre既存342点の原本とランキング根拠を取得し、1カテゴリの先頭20点程度を読み込み、信号付き候補出力・重複排除・途中再開をオフライン検証。元の順序がランキングか不明なら順位不明とする。評価順CSVを小さく追加して異種信号を混同しない確認。候補から3〜5点だけ日本の販売状況・品番一致の仕入/競合を許可された方法で実地確認。既知の候補を入力して再現しただけの試験と、新しい商品を自力で発掘する試験を区別。ライブが許可された店1店・1カテゴリで新規候補抽出を1回実施し、候補根拠・実測価格/在庫・失敗件数を提出。新規発掘できない場合は未合格とし、固定8候補で代替しない。成果は収集行数でなく根拠付き発掘候補、買付可能性確認、価格照合、重複ゼロ、再開成功で判定。
