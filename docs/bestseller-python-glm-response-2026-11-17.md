## 売れ筋商品発掘パイソンの最適形

**結論：**
オーナーの仮説通り「各店舗を回って集計する形」が最適です。ただし全カタログを収集するのではなく、各店が持つ「売れ筋の信号（ベストセラーページやレーティング順など）」のみを抽出し、共通のSQLiteに集約して重複排除とランキングを行うパイプラインを提案します。

### 1. 対象店舗と、各店で使う「売れ筋」の信号
- **Notre**: ベストセラー並び順（既存の342点データを流用）
- **Foot Locker**: カスタマーレイティング順（既存CSVを流用。※規約上は自動収集禁止ですが、2026-11-15のオーナー指示によりレイティング順取得を実行）
- **Converse**: カスタマーレイティング順（既存CSVを流用）
- **BSTN**: 人気商品・注目商品の信号（現在収集中のDBから該当フラグのあるものを抽出）
- **Patta**: ベストセラー並び順（日本IPでは429のため、VPN環境時またはMuseの手動ブラウザ収集データを待ち受け）

### 2. 集計の形（回り方、重複の扱い、ランキングの付け方）
- **回り方**: 各店の売れ筋ページ（最大数百件）または既存CSVを順次読み込み、全件SQLiteに保存。全カタログ収集は行わない。
- **重複の扱い**: ブランド名＋モデル名（品番）をキーにして正規化。複数店で被る商品は、価格・在庫状況などの条件で最も有利な1店をメインレコードとし、他店は「その他買い付け可能店」としてサブ情報として残す（2026-11-16方針に準拠）。
- **ランキングの付け方**: 「複数店で売れ筋に入っているか（マルチストア合致）」「レイティングの高さ」「直近のトレンド」をポイント化し、総合スコアでランキング付ける。

### 3. 保存先と出力形式
- **保存先（正本）**: SQLite（`trend_items.db` 等を新規作成。既存の収集DBとは分離）。
- **出力形式**: 確認用にCSV出力（`売れ筋ランキング_YYYYMMDD.csv`）。オーナーがExcel/スプレッドシートで確認しやすい形にする。

### 4. 実行形態（手動スタート、再開、429やIP制限への対処）
- **実行形態**: iMac上でダブルクリック（`.command` または `.sh`）で手動スタート。
- **再開機能**: どの店のどのページまで取得・読込したかをSQLiteの `progress` テーブルに記録し、止まっても再開で続きから処理。
- **429・IP制限への対処**: リクエスト間隔を長めに設定（5〜10秒）。429が発生したら即座にその店の処理を中断し、次の店へスキップ。VPNの切替は行わず、エラーをログに残して停止する（MuseがVPNを手動切替後、再実行で続きから）。

### 5. 最初に試す最小の形（1店だけの試験など）
- **Phase 1（外部通信なし）**: まず既存のCSV（Foot Locker / Converse）とシート（Notre）をPythonで読み込み、SQLiteへ格納 → 重複排除 → CSV出力までを行う。これで集計ロジックと重複排除が正しく機能するか検証する。
- **Phase 2（実スクレイピング）**: Phase 1が合格したら、BSTNの売れ筋ページ1ページ分（数件）をPythonで取得し、同じパイプラインに流す。
