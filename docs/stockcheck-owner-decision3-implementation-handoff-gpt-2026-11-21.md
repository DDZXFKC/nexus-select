# 在庫確認・最終オーナー決定の実装引継ぎ（GPT、2026-11-21）

## 優先する確定要件
1. 問い合わせ受付時刻から**5分以内**に回答メールを送信したことをログで検証する。内部締め切り目安は受付から4分。結果：IN_STOCK/OUT_OF_STOCK/取得不能などの理由を説明する返信。MAIL送信不能のとき成功扱いにしない。
2. 店サイトへの接続不能（403/429、接続失敗、タイムアウト、5xxなど）のとき、**今その店のサイトにつながらず在庫を確認できなかった**という内容と、**時間をおいて再度この商品ページから在庫確認をお願いする**旨を5分以内に返信。断定的な在庫切れ通知は禁止。
3. 5秒などの短時間・即時再試行は可。**1時間後/6時間後の遅延再試行、確認中の長期保留、24時間の追送約束、48時間/14日の自動期限切れは禁止**。取得不能により処理した依頼は新規受付を妨げない終状態にする。
4. 取得不能となった買付先を運営へ知らせる（ショップコード、URL、HTTP状態、証拠、取得時刻。機微情報は伏せる）。403/429のサイトへの回避アクセスは禁止。1店の障害でほかの店の処理を止めない。
5. 問い合わせ記録は**対応終了から90日**で削除。プライバシーポリシーに「6か月」の記載が残っていれば90日へ変更する。注文・会計・法的保存義務のある記録は別制度で管理。
6. 同一商品の複数買付先は比較可能な総原価見込みの安い順に確認する。買付先から取得する商品ページ1回の応答で在庫と現在価格を取得し、在庫ありの店ごとに販売価格を再計算。確定可能な中で再計算販売価格が最安の店を採用する。掲載価格より高い差額が**400円未満なら掲載価格**、**400円以上なら新価格を案内**、安い場合も掲載価格。表示中の商品価格は勝手に書き換えない。
7. 商品照合は別系統の照合v2検収が済んだ根拠付きSKUに限る。候補仕入先URL、在庫サイズ、条件・原価の不足を勝手に推定しない。全店在庫切れが確認できた場合のみ在庫なし。未確認の店舗が残っていればその理由を説明し、不確かな在庫断定を避ける。
8. 価格変動の注意は返信メールに書かず、サイトの取引注意事項と在庫確認ポップアップに記載する。受付と結果の二重メールや手動ゲートは追加しない。
9. 新正本はXServer（PHP 8.3.37、WP-CLI利用可能）。**Localに反映しない**。変更前にXServerの現行mu-plugin・商品メタ・バックアップを確認し、Basic認証/noindexは維持する。資格情報はGitHubに保存しない。

## Claude最終設計を受けて実装する順序
1. 新設計とこのチェックリストの矛盾をゼロにする。5分メール/取得不能/複数店舗/価格ルール/90日削除が全て設計されていること。
2. 現行サーバーの`ahc-stock-check.php`と買付先URL/価格データの保存形式を読み、問合せ取得・結果保存と送信CLIの最小差分を作る。
3. ストア別StockChecker（在庫・現在価格・証拠）、OfferResolver、必要費用を含む再計算器を分けて実装。ネットワーク制限・タイムアウト・レート上限・30分キャッシュ。アクセス不能時は説明付き最終返信を作る。
4. WordPressメール送信経路を接続し、受信から送信までの時間とメール本文を自動アサーションする（5分未満、遅延再試行ジョブ0）。
5. ショップごとの mock HTTP（あり／なし／接続不能／価格不明／403／複数候補／400円境界）でE2E合格後、XServer作業場のバックアップを取り、限定的に反映。既存注文・商品ページの副作用をチェック。
