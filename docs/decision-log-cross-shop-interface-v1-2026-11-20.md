# Decision log — cross-shop CSV interface v1 (a3789459)

GLM検収（2026-11-20）：**条件付き承認**。全文は docs/review-glm-gpt-docs-2026-11-20.md。

## 確定した判断
- 採用粒度はカラーウェア単位（横断キーと同一粒度）。サイズ別採用は行わない。GPTの設計ゲートはクローズ。
- 既知の限界として明記：採用元が全サイズで最小価格とは限らない。サイズ別の最終判断は購入時点で行う。

## 実装着手前の条件
1. 採用元のサイズ別価格・stock_observed は観測列として全件出力に残す。候補間でサイズ価格に乖離がある場合のフラグ列（例：size_price_divergent）を追加（順位には影響させない）。stock_observed には観測時刻の出所をスキーマに明記。
2. **仕入総額の原価基準の粒度（ロット＝カラーウェア単位か、サイズ単位か）を明記。未確定なら実装着手不可（唯一デザインを変え得る条件）。** 参考事実（魔王ちゃん）：SP・FLの現行マージンCSVはカラーウェア単位で単一価格を持つ。
3. 資格定義を一行で厳密化：資格＝「原価計算済み かつ 仕入総額検証済み」。順位チェーン3番目の原価計算済みフラグは資格と重複し常に真になるため、防御として残すなら注記を付ける。
4. HOLD理由コードを候補ごとに出力（cost_uncalculated / total_unverified 等）。
5. 正規化のフィクスチャ化（ブランド表記ゆれ・全角半角・商標記号、色コードの前置ゼロ・区切り・大小文字）。FL/SP既存CSV→source offer input v1 の変換器には往復テストとキー重複監査を必須とする。FL確認リスト6項目の結果をこの変換器フィクスチャに反映させる。
6. タイブレーク最終段の安定行IDの導出規則を文書化。
